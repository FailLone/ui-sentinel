## 1. 必需与可选：来源先于预算

| 类别 | 权威来源与处理 |
| --- | --- |
| 必需检查 | 冻结任务/用户明确目标、原采样协议的公共检查要求、默认采样底线、适用规则/开放调查、已经selected的所有事项及真实未解决动作。先绑定到已有scope事项；未映射的必需项不能因为列表为空便消失。 |
| 可选扩展 | 当前目标与原协议不要求、默认采样已经覆盖、尚未准入的新变体/新访问/追加调查。存在控件或公开谓词本身不意味着所有变体都必须再查；本例Name排序已验证后，Price是额外变体。用户若明确要求Price和Name，两者都必需。 |
| 尚不能确认来源 | 不允许模型只贴“可选”标签。先确认其与原目标/公共范围的关系；无法映射的必需需求以现有scope保留具体未验证原因，不能宣布全部满足。 |

运行时来源必须是原目标、冻结公共任务范围和页面公开证据，不得使用样本ID、隐藏故障标签或评分答案。筛选与排序是不同公开效果，排序的不同选项是同一效果的变体；是否都必查取决于原目标/协议，不由预算决定。初始范围声明需列出必需来源→真实item/ref的映射；“映射闭合”由可信来源和登记事实核对，不能由模型一句“都覆盖了”确认。无法通用判断的自然语言目标保持未验证/澄清，本轮不新增Goal语义编译器。

**准入是承诺点：** 可选检查一旦通过原 `selectItems` 或真实动作进入scope，就成为必须履行的已选义务。不能删除、取消selected、改成optional/excluded，或借sampling-cap/预算理由抹去。既有、真实的not-applicable/契约边界判定保留；不把质量发现当阻断，也不忽略真实阻断。

## 2. 必需与证据满足后：进入不可扩展的收尾

1. 在已有工具/模型轮次的安全边界，先按原流程flush/drain并检查取消、真实执行错误、未知写入；完成必需项的scope登记。用**同一事实收集器和原完成函数**只读预判，不用`pending总数`、空规则队列或模型总结代替。
2. 所有必需项已映射，原 `scope-covered` 判定接受，证据可读/归属/完整性条件满足且无在途工作时，进入执行器拥有的closing栅栏。此后拒绝新的选项、返回/导航和可选调查；同轮已经排队的扩展也只能无副作用拒绝，不建立action或scope承诺。
3. 在安全边界直接调用**原 `finishUiScan(scope-covered)`**：seal、再次判定、生成原proof、持久提交及历史校验。无需再等模型“想起”run_finish；只读预判不生成有效终态，不能替代提交。
4. 栅栏后事实变化、取消、真错误或未知写入仍按原优先级处理；不得凭早先ready缓存完成。原门拒绝时保留已有义务，按原可信blocker/partial/error路径结束，不恢复可选探索。不给工具修正、F1、重试或预算增加新机会。

## 3. 可选检查：先有界准入，再选择或访问

只在closing尚未锁定、且不挤占必需工作时评估。准入点在 `selectItems` **及任何会增补范围的实际访问/动作之前**；导航许可只是安全边界，不等于检查必要性。

按执行器当前时间、已用动作/模型调用计算三个维度，要求 `剩余 >= 必需剩余上界 + 本次扩展上界 + 原收尾保留`。扩展上界包含访问、绑定、必要读取、动作、后置测量与已有允许重试；不靠成功平均耗时，边界不明则不纳入。沿用原caps及phase tracker保留值（本预算为60秒、2模型调用）；deadline嵌套不得重复扣算，也不能漏算。拒绝可选提案不延时、不重置进展计数、不产生“已选未验证”假事项。费用仍沿用原网关/共享账本预留与停止条件，不新建资金池；费用unknown等原安全停止优先。

未纳入部分记录“范围外/未准入的可选检查、来源、预算理由”，不报pass、fail或已验证，不制造blocker。已选或任务必需但做不完的项目留在原ledger，按旧门产生partial/blocked；不得改叫可选以换取covered。新页面会带来默认采样义务时，其成本也须在访问前计入，不能先访问再推说只是可选。

## 契约差异与最小实现范围

| 当前 | 提议差异 |
| --- | --- |
| scope主要记录已选工作；Goal/协议的必需来源可能尚未完整表达 | UI范围声明先把**原必需范围**登记到已有scope，附可审阅来源；不降低原标准。 |
| 主要靠模型请求、无进展或预算保留触发收尾 | 必需映射闭合后，以原门的真实ready驱动closing和原finisher。 |
| selectItems/合法导航缺少扩展预算准入 | 增加UI-only准入检查与实时预算预约；拒绝在承诺/派发前发生。 |

## 3. 阶段一：定位首次分歧

对齐 A/B 的业务状态和调查目标，不机械对齐请求序号。检查 seq 13–20，并向前找到进入循环的第一次分歧。

逐次记录：

| 字段 | 要回答的问题 |
| --- | --- |
| 目标及未决假设 | Agent 此时具体要确认什么？ |
| 模型实际收到的内容 | 所需信息已存在、被省略、被截断，还是表达不清？ |
| 请求与响应 | 是重复 page_observe、等待反馈，还是展开特定细节？ |
| 事实变化 | 与上一观察相比，新增了哪些决策相关事实？ |
| 工具可用性 | 元素引用、详情读取、证据引用是否可解析且未过期？ |
| 判断结果 | 是否推进了假设、结论或合理结束？ |
| 下一步原因 | 为什么仍然不能行动、验证或结束？ |

优先核查：

- 精简结构是否遗漏可操作性、遮挡、业务反馈或预期所需字段。
- page_act 的新观察是否明确返回并进入当前上下文，随后 page_observe 是否重复读取。
- 短元素引用是否能被动作工具接受，状态过期提示是否导致反复重定位。
- 详情工具是否存在、描述清楚，并能真正返回所需字段。
- 旧历史与最新观察是否相互矛盾或掩盖了新状态。
- 截断 JSON 是否损坏结构，或恰好截掉决定下一步的结果。
- 异步反馈是否仍在等待，页面变化是否未被正确观察。

交付：在 plans/observation-loop-regression-findings.md 记录版本、运行引用、关键序列、根因证据和替代解释。文件在调查后创建，不预填确定结论。只记录可审阅事实和简短决策说明，不索取隐藏思维链。

阶段门槛：至少取得一个可解释的失败轨迹和可验证的根因假设，再修改相关实现。

## 4. 阶段二：最小协议修复（B1）

根据证据选择修改，不要求把下列措施全部实施：

- 恢复决策必需的摘要字段，完整细节仍按需获取。
- 修复元素引用解析、新鲜度与状态失效机制。
- 明确动作返回已采集的状态、证据及仍需等待的内容。
- 修复详情工具、摘要组织和结构化结果截断。
- 清楚区分“没有变化”“未采集该事实”“观察失败”。

建立与根因对应的确定性回归测试，例如：部分遮挡没有被摘要成完全可用，动作后的结果正确进入上下文，过期引用不会误点其他元素，详情可以恢复被省略的事实。

保留五点采样、单步循环和现有预算，单独形成 B1。不要顺带重写 Agent 框架或修改评分器以放宽验收。

## 5. 阶段三：无进展检测（B2）

目的：防止已知的无新增信息循环持续消耗预算，不替代根因修复。

### 判断依据

使用观察范围/参数、相关页面状态、假设或验证目标、已有证据和等待条件形成进展记录。不以 URL 不变、截图相似或连续工具名称相同作为充分依据。

进展包括：新事实、新的有效验证、假设支持/反驳、证据补全、未决问题解决、合理终止。仅重新生成 snapshotId、时间戳或换句话总结不算新事实。若执行层不能判断语义进展，就保留不确定性，不能伪装为准确识别。

合法的异步等待必须有目标条件、期限与采样间隔。等待过程不因没有点击而被熔断，但依然受运行和工具预算限制。

### 分级处理

1. 对满足新鲜度条件的重复请求，返回简短的 no-new-facts 反馈和已有证据引用，避免重复发送完整页面。
2. 提示未决目标及可用替代方案：展开具体细节、改变验证方法、进行有条件等待，或记录无法判断并转向其他检查。提示不是完整行动白名单。
3. 持续无进展达到可配置阈值时，标记当前调查停滞，保留 unknown/inconclusive 与原因，转向独立工作。
4. 没有其他可推进工作时，通过现有运行状态契约诚实结束或停止；不得把停滞映射为成功。若现有结构无独立分支状态，先使用已有假设/覆盖记录表达，不额外建设分布式任务系统。

阈值是实验配置，固定到运行清单；不能把“3 次观察”当作正确性标准。任何有限去重记录都要在相关状态、目标或有效采集条件变化后失效。日志保留实际请求、复用、抑制、恢复和停止原因。

禁止强制业务动作、强制 run_finish 为成功、绕过未决写操作、禁止所有后续观察。状态新鲜度无法确认时，允许重新采集并计入预算。

必要测试：相同状态重复观察被识别；延迟业务反馈不被误熔断；焦点/滚动/弹窗变化使复用失效；新的有效验证不误算循环；无限无效等待仍受限；取消、终态和未知写操作限制保持有效。

## 6. 阶段四：历史去重与压缩（B3）

先测量实际请求的组成，再处理最大的重复来源：

- 当前完整状态摘要只保留一份，避免 latest 与历史工具结果重复携带。
- 历史工具大结果留在证据层，上下文保存结构化摘要与引用。
- 明确保留目标、要求、未决假设、已尝试的方法及结果，避免忘记失败尝试后再次循环。
- 权限、剩余预算、未知写操作、停止条件不能被摘要删除。
- 摘要不能把 unknown 变成 pass，不能把视觉推断变成测量事实。
- 详情读取遵循 run 归属、大小限制和预算；报告仍能访问原始证据。

独立测试关键约束保留、旧尝试可恢复、引用归属、摘要与原始结果一致。单独形成 B3，不同时改变 maxSteps、模型或采样数量。

## 7. 对照与验收

保留清晰的累计对照版本：

| 版本 | 内容 |

| B | 原始精简观察失败版本 |

| B3 | B2 + 历史压缩 |

此处 B1–B3 是本次局部实验命名，不等同于上一计划的 C/D/E。

### 验证顺序

1. 运行相关确定性测试，先确认协议、状态、证据与取消预算约束。
2. 对退化场景做相同配置的重复真实模型运行，初始每版本至少 3 次；固定试验次数并保留全部结果，不只挑成功记录。
3. 若关键指标波动或原因仍不明确，再增加有说明的重复实验，不无限试到通过。
4. 选择候选修复版本，通过正式 API 运行 minimum：C0–C5 各 3 次，完整保存 18 次记录；保持原门槛和独立评分。

报告比较：业务结果、有效发现、误报、unknown、覆盖、证据完整性、无进展序列、请求数、总输入/输出 token、耗时、观察复用与实际采集数。失败运行因提前终止而成本更低，不算优化收益；成功运行成本与整体失败率分别展示。

模型配置、规则、靶场、预算、代码和锁文件版本均保存。工具调用、generate() 调用和实际供应商请求分开统计；usage 缺失保留未知。实验之间隔离数据并重置，不允许学习规则污染下一轮。

验收要求：

- 根因有轨迹和测试支持，而不是只加提示词后偶然成功。
- 同类无进展循环受到控制，同时合法观察和异步验证仍能进行。
- 现有 C0–C5 门槛通过，无已知新漏报、误报、证据或资源安全回归。
- 成本收益用完整运行比较；小样本只表述为初步结果，不承诺普遍收益。
- 未完成真实模型评估时，明确列为未验收，不宣称问题解决。

## 8. 交付与回退

每个阶段独立提交，保留可复现配置与关闭优化的方式。新日志与摘要标注结构版本，原始证据不可覆盖。先恢复稳定协议或关闭有问题的优化，不删除失败实验记录。

编码 Agent 最终交付：

1. 根因调查文档与相关运行/证据引用。
2. 最小修复、无进展检测、历史压缩的实际完成范围及提交。
3. 必要测试和真实模型对照结果；未完成项目、凭据或能力缺口。
4. 回退步骤与已知限制。

本计划不要求升级模型、提高预算、减少采样或开启多步循环。若证据表明需要这些变化，另列后续提议，不混入本轮因果验证。

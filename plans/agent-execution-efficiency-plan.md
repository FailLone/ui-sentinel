# Agent 执行效率优化计划

日期：2026-09-22  
状态：待实施；本次仅记录计划，不代表优化或真实模型评估已经完成。

配套：[探索策略与未知问题发现](../docs/exploration-strategies.md)、[执行层设计](../docs/execution-engine.md)、[最小验证计划](./minimum-validation-plan.md)、[最小验证进展](./minimum-validation-progress.md)。

## 1. 目标与边界

减少重复模型输入、无新增信息的页面观察和无进展循环，在相同预算下保持问题发现、业务覆盖与证据质量。先改善信息传递，再调整执行循环；不以提高预算掩盖效率问题。

用户提供的诊断截图记录了 30 次模型调用、11 次实际动作、40 次页面观察、平均约 17,795 input tokens/调用，以及 hitSamples 占快照约 81%。这些是待核验的单次运行线索，不是已复现的基准，也不能据此保证减少 60% payload 或 40% 模型调用。

无浏览器动作不等于无效调用：提出假设、排除误报、形成结论和合理结束都可能有效。一次 generate() 也不等于一次模型请求。

第一轮实施范围限定为阶段 1–3：统计、观察压缩、重复观察消除。保持五点采样和现有单步循环。阶段 4–5 在获得可解释结果后开展，不自动改变现有 C0–C5 的验收标准。

## 2. 不可退让的约束

- 完整事实保留在证据层；默认模型输入可以精简，原始证据不能丢失。
- 摘要、模型推断和实际测量分别记录，unknown 不能压缩成 pass。
- 有限采样只能说明已测点，不能推断整个交互区域均正常。
- 权限、资源冲突、取消、预算、终态检查对每次实际操作持续有效。
- 写操作结果未知时继续沿用核对与阻断机制，不因观察复用盲目重试。
- 页面状态变化使定位失效时重新定位；禁止把坐标点击自动纠正到中心来掩盖缺陷。
- 只允许复用同一运行内满足新鲜度条件的观察；跨运行评估不能复用旧结果。

## 3. 阶段 1：固定基线与补充统计

### 执行步骤

1. 核对当前源码、依赖和正式运行记录，确认截图中各指标的统计口径。
2. 为真实模型请求关联 run、请求序号、用途、模型、耗时、usage 和失败状态。主模型、视觉模型及重试分开记录，同时计入总预算。
3. 记录输入各部分的字符数或字节数：协议、当前快照、规则、历史工具结果、工作摘要。若使用 tokenizer 估计 token，标注为估计，不能冒充供应商实测 usage。
4. 关联观察、页面状态、动作、假设、验证和发现，区分重复读取、有效判断、有效结束与无进展响应。无进展分类保留可审查依据，不能只用是否调用工具判断。
5. 固定模型配置、代码与锁文件版本、规则修订、提示词、靶场版本和预算，运行基线 A，保存所有成功、失败、超时和 invalid 记录。

### 交付与验收

- 可关联到证据的运行统计和基线清单。
- 实际请求数与预算统计一致；缺失 usage 标为未知，不填零。
- 能解释一次运行中重复输入、重复观察及无进展发生在哪里。
- 缺真实模型凭据时明确记录基线未完成；mock 测试不能替代真实成本和发现能力评估。

## 4. 阶段 2：精简观察协议，保留采集覆盖

### 执行步骤

1. 在执行层保留完整快照、五点采样、完整定位信息和原始证据。
2. 引入绑定快照/状态的短元素引用，完整节点信息集中存储，采样点引用节点，避免重复 selector 路径。
3. 给 Agent 默认返回组件语义、必要几何和命中摘要；提供按目标和证据引用展开详情的受控工具。详情读取计入预算并限制大小。
4. 元素引用解析执行运行归属及新鲜度校验，过期返回明确状态，由 Agent 重新观察或定位。
5. 用同一份采集事实对比新旧输出，验证摘要与详情一致，规则仍使用完整事实。

拟定输出示例（不是现有工具接口）：

```json
{
  "snapshotId": "s42",
  "elements": [{
    "ref": "e12",
    "role": "button",
    "name": "提交订单",
    "hitSummary": { "sampled": 5, "blocked": 2, "blockerRefs": ["e27"] },
    "evidenceRef": "ev123"
  }]
}
```

### 交付与验收

- 精简观察结构、详情读取契约、引用过期处理和版本标识。
- 模型可从摘要发现异常并取得原始证据，部分遮挡不能被摘要成完全可用。
- 通过事实一致性、证据归属和过期引用测试；得到对照版本 B。
- 报告完整运行输入总量及详情展开成本，不能只比较单个快照大小。

## 5. 阶段 3：合并动作后观察，消除重复读取

### 执行步骤

1. 审计动作工具已经执行的采集，复用其结果形成动作后状态摘要与证据引用，避免再增加一次重复采集。
2. 让 Agent 明确知道动作返回了哪些新事实、哪些仍未知，以及是否需要继续等待。
3. 建立可验证的新鲜度契约，区分截图、布局、命中、焦点、业务反馈等事实。不能只按 URL 或 DOM 未变化来认定所有观察仍然有效。
4. 对滚动、视口变化、弹窗、焦点、异步反馈及布局变化进行失效处理；不能确定是否新鲜时重新采集或返回 unknown。
5. 允许 Agent 请求强制重新观察并记录目的。历史快照保持不可变，不把新状态覆盖到旧证据引用中。

### 交付与验收

- 动作结果与必要变化摘要，观察复用/失效日志。
- 重复观察减少，仍能发现延迟反馈、弹窗、焦点和同 URL 的状态变化。
- 覆盖状态失效、延迟反馈、取消与未知写操作回归；得到版本 C。
- 第一轮到此评审：汇总 A/B/C 的收益、发现质量和局限，决定是否进入后续阶段。

## 6. 阶段 4：历史压缩与多步循环实验

先进行历史压缩，单独形成版本 D：

1. 当前快照仅保留一份，旧工具大结果替换为结构化摘要与证据引用。
2. 保留目标、关键要求、未决假设、未知写操作、权限、预算和停止条件。
3. 验证 Agent 能通过引用取回必要证据，不因摘要丢失约束或重复探索。

再将 maxSteps 做成实验配置，在 D 上比较 1 和 3，形成版本 E：

1. 核对当前 Mastra 版本的实际请求行为，确认内部每次请求都受预算与取消控制；不能仅在外层 generate() 计数。
2. 每次工具执行继续检查运行状态、权限、资源与终态；依赖页面状态的动作保持串行。
3. 覆盖迟到模型响应、取消、预算耗尽和 run_finish 后禁止继续操作。
4. 比较实际模型请求数、总 token、耗时及发现质量；不预设多步一定更省。

如果无法约束内部请求或新循环损害可靠性，保留单步配置；前面的观察优化可独立保留。

## 7. 阶段 5：独立对照评估

| 版本 | 唯一新增变化 |
| --- | --- |
| A | 基线与统计 |
| B | 精简观察输出 |
| C | 观察复用 |
| D | 历史压缩 |
| E | 多步执行 |

### 现有最小验证集

- 每个候选版本通过正式 API 执行 C0–C5，各 3 次，共 18 次，全部记录保留。
- 继续使用最小验证计划的门槛与独立评估器；每批隔离数据、重置场景并固定规则，避免前一批学习影响后一批。
- 同时比较发现、误报、unknown、业务覆盖、证据完整性、实际请求、总 token、观察/动作数和耗时。失败运行的低成本不能作为优化收益。
- 18 次是回归门槛，不能单凭细微变化证明稳定收益；结果波动或出现质量退化时，先调查，再增加重复验证。

### 补充交互回归集

单独建立套件，不静默修改 minimum 的 C0–C5 定义：

- 局部遮挡而非完全遮挡。
- 视觉输入区域宽、实际 input 窄，留白点击不聚焦。
- 同样外观但外层容器正确代理聚焦。
- 合理异步聚焦，以及独立图标操作等反例。

用独立评估依据核验场景及焦点/命中证据。分别测试提示缺陷后的定向验证，以及不提示缺陷的自主发现；后者不能从答案或套件名称泄漏可疑位置。相关采集能力若尚未实现，记录阻塞和未覆盖，不宣称已通过。

这些已讨论案例属于开发/回归材料，不能作为未见问题泛化证据。自主发现失败需判断是否为原有能力缺口，不能直接归因于本次性能修改；定向验证回归与探索能力不足分别报告。

## 8. 发布与回退

每个阶段独立提交，实验配置记录到运行清单。先通过相关确定性测试，再做真实模型对照。未取得模型凭据时可以完成结构和可靠性测试，但不能宣布真实效果验收完成。

发布候选必须通过现有质量门槛，且观察摘要、证据获取、异步状态和取消预算约束没有已知回归。出现新增漏报、误报或覆盖降低，先定位并修复，不能用节省 token 抵消。收益不足时保留更简单的实现。

压缩输出、观察复用、历史压缩和多步循环应能独立关闭或按提交回退。历史证据及报告需带结构版本，避免回退后无法读取。

最终交付包含：代码变更、协议说明、必要测试、A–E 中已完成版本的原始记录和对照报告、未完成项及回退方式。报告明确区分已测事实、估计值与尚待验证的收益。

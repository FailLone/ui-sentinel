## 证据分析：实现与实验协议

实现单页面操作者 + 冻结证据消费者；已有 Mastra `.parallel()` 合并视觉与几何分析，任务队列允许与主 Agent 独立工作重叠。视觉候选仅进入假设，不直接批准缺陷。失败重试的覆盖判断由执行与报告共享。

`visual-1` 协议在付费前固定：同一提交两份隔离服务，baseline 为 serial、candidate 为 parallel；C0/C2 各两对，共八轮，交替顺序。相同入口、1280×720、同一个 checkout 视觉问题、同一模型及供应商、300s/30 请求/40 动作上限，整批估算成本上限 $0.50。每轮必须恰好完成一个规定问题的视觉分析，结果消费在结束之前，证据可读、候选已验证，原 C0/C2 质量门槛也必须通过。

健康场景不应报告该问题的视觉候选；遮挡场景应提出 occlusion 候选。记录视觉分析开始/完成、首次发现、报告可用时间，以及分析期间主模型发起请求数。串行与并行分析相同任务；不与“没有视觉分析”的旧版本混比。性能参考门槛仍为耗时下降至少 15%、请求和 token 不增加；缺 usage 或不同供应商不宣称可比。遇到质量失败保留并停止该批，修复须新批次。该小样本不能证明稳定尾延迟。

## 动作复用审计

沿用现有 `journeys/runner.ts`，不新增另一套 Browser Use/Stagehand 执行器。已检查每步前置条件、唯一语义目标、动作结果与后置条件；异常或业务边界立即交回，取消通过 guard 传播。executor 在 journey 内持续禁止业务写入，片段提取要求原动作有显式零写入证据。当前测试覆盖异常中断、变更、歧义、取消、证据缺失及写入屏障。通用冷启动动作批次和 Midscene 新缓存仍按计划暂缓。

C2 的 Qwen 分析成功，识别出遮挡且证据与已有内置规则发现一致。但新视觉假设处于 open；原指令要求避免重复发现，原工具又缺少关联既有发现的入口。下一次 DeepSeek 用尽 4096 输出 token，全部为 reasoning，未形成工具调用，运行 execution-error。契约缺口与失败同时存在，但不能据此证明全部额外推理都由该缺口造成。未知探索质量/完整收尾未通过，不继续剩余三轮。

修复：增加由 Agent 显式调用、受相同冻结证据及真实命中采样约束的 `hypotheses_link_finding`，复用已有发现解决视觉假设；不自动认可候选、不修改规则判定、不提高模型输出或运行预算。同时修复拒绝不完整流响应时丢失已收到 usage 的记账问题。上游该次用量已知（9160 input + 4096 output），旧运行报告仍保留原状，不追改历史成绩。

### 第二次视觉批次：关联成功，重复调查仍导致失败

`data/efficiency/2026-09-23T14-14-20-847Z`，提交 `702e5ff`。四轮 C0 全通过；第五轮 baseline-C2-1 的视觉候选正确关联已有发现，假设已 supported，但 Agent 随后又执行了约八秒通用测量，并在下一请求耗尽输出上限，运行 execution-error。该批停止，剩余样本未执行。失败请求的 usage 已由修复后的执行层保留。

为减少重复运行已通过场景的开销，增加 `visual-diagnostic`：仅在候选 parallel 模式下运行 C2 一次，仍使用同一视觉问题、原质量检查和原预算，估算支出上限 $0.15。它只用于故障定位，不替代后续固定八轮串并行比较，也不计入正式十八轮。每次修复都冻结新提交，失败不覆盖。

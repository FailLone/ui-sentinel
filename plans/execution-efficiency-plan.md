# 下一轮开发：执行效率与能力复用

日期：2026-09-23。状态：P0 工程实现已完成，正在进行真实四轮诊断；P1–P4 尚未开始。本文件是下一轮开发入口，可交给编码 Agent 执行；完成一阶段后记录代码版本、验证结果与下一阶段，不把计划目标写成已实现能力。

依据：[当前进度](./minimum-validation-progress.md)、[M4 验收](./acceptance-results-2026-09-23.md)、[M5 复查](./learning-validation-results-2026-09-23.md)、[总体架构](../docs/architecture.md)。

## 1. 目标与范围

在相同质量要求、模型和预算下，减少重复决策、采集及检查，让已知场景复查比重新探索更省；同时保留未知问题的发现机会。

保留 TypeScript、Mastra Agent/Tools、Playwright、Midscene、现有 API/工作台和存储。先完成 P0–P4 的购买靶场效率闭环；业务适配和主动视觉检查列为下一阶段 G1/G2，各自验收。此轮不迁移框架、不升级依赖、不引入多个付费 Agent 或分布式调度。

Agent 仍决定探索方向、语义绑定、异常调查和结束请求。执行器负责确定的采集、检查、证据保存和状态校验。路径复用是 Agent 可选择的能力，不将所有检查改成固定脚本。

## 3. 全阶段不变的约束

- 每轮仍为 300 秒、30 次实际上游模型请求（含视觉和失败/重试）、40 次动作；单请求与工具期限沿用当前配置。不能提高预算或减少检查范围取得通过。
- 当前一笔订单及未知写结果核对机制不变。每个动作继续经过权限、阶段、预算、取消、尝试有效性校验；SDK/网关不能增加隐式重试。
- 业务结果、执行结果、检查覆盖、规则判定分开。系统可停止失败任务，不能代替 Agent 伪造 `run_finish` 成功，或因为支付成功就宣布检查完成。
- 保留动作前必要证据、缺陷原图、测量、恢复前现场及证据归属。C5 仍使用已批准的完整五秒测量，不缩短窗口、不改成从响应开始计时的另一种声明。
- 新问题继续走假设、测量和证据流程。无适用规则不能解释为无问题；未知事实、缺失资格和语义歧义保持 unknown。
- 保留所有失败、超时、取消、未知 usage、模型输出及恢复过的工具错误；公开摘要不包含密钥、私有答案或隐藏推理。
- 不修改已批准规则的声明。原候选批准可用于同一声明的隔离复查；新声明不得自动启用。源验收数据库、历史结果目录和人工反馈不能覆盖。

## 4. P0：建立可比较的测量与实验入口

**目的：** 在优化前能解释一次 Run 的时间花在哪里，以及改动是否损失质量。

文件落点：`src/execution/executor.ts`、`model-request.ts`、`request-tracker.ts`、`scripts/experiments/`、`evaluation/private/`。优先复用现有事件和实验网关，不再建一套 Agent 循环或评分器。

交付：

1. 为观察中的截图、DOM、a11y、规则评价、证据持久化补有父子关系的计时；沿用请求/工具事件。记录 wall time、互斥阶段时间和嵌套耗时，明确 unavailable，不能重复累计。
2. 每轮摘要增加：实际请求数、已知/未知 usage、费用、完整/轻量/复用观察数、检查执行/复用/跳过数、工具错误、无事实进展轮数、finish 拒绝/接受数、业务写次数。观测复用必须有原因和源证据。
3. 新建 `scripts/experiments/efficiency.ts` 及 `experiment:efficiency` 命令。支持两个不可变 Git 提交的独立构建、独立数据库/端口/浏览器、串行重置和交替 A/B 顺序。由私有 runner 选择场景，Agent 只收到相同公开目标。
4. 保存 manifest：两个完整提交 SHA、源码/构建哈希、锁文件、工具/提示词/规则修订、完整非秘密配置、模型与实际供应商、请求策略、顺序、评分器版本、起止时间。供应商不符合固定配置时记为不可比，保留运行，禁止换路由后混入。
5. 先读历史数据做统计复现，再运行小批真实对照。仪表化本身不得改变提示词、工具 schema 或执行决策；如果必须改动，作为独立版本记录。

P0 已提供的命令契约：

```sh
pnpm experiment:efficiency -- --baseline-ref <SHA> --candidate-ref <SHA> --phase diagnostic
pnpm experiment:efficiency -- --baseline-ref <SHA> --candidate-ref <SHA> --phase compare --learning-source <已关闭且已批准的学习目录>
```

`diagnostic` 固定 C0、C2 各一次/每组，共四轮；`compare` 固定 M5 异常/正常各三次/每组，共十二轮。后者复制同一已批准声明到两组隔离数据库，使用完整购买与质量检查目标，禁止只把 Agent 送到结果页后比较。缺文件、缺凭据、规则修订不匹配或模型不可用必须明确失败，不静默 mock。模型固定使用当前实验网关的 DeepSeek/Qwen 型号；主模型供应商默认固定为最近通过的 Wafer，并记录实际值，不在本计划中更换型号。

两组必须使用相同的私有评分器与公开任务，记录评分器哈希；不能让不同提交自带的不同门槛各自给自己打分。旧版本缺少新增性能字段可记 unavailable，但不可缺少质量评分所需事实。新增差分字段不能破坏旧报告读取。

**验收：** 历史六轮请求数和时间统计可复现；嵌套耗时不重复计入总量；失败/超时不丢记录；两组环境隔离；命令拒绝不完整的实验配置。先用本地确定性 fixture 验证编排，不以 fixture 证明 Agent 能力。

## 5. P1：减少重复决策与观察

文件落点：`executor.ts`、`browser.ts`、`element-store.ts`、`decision-memory.ts`、`run-phase.ts`。必要时抽出观察协调器，避免继续扩大单个执行函数；不为拆分而改变行为。

### 5.1 一次工具完成确定的后续工作

`page_act` 保持一个业务动作，内部完成合法性验证、必要动作前证据、动作、反馈边界、事实更新、适用的确定性检查与结果保存。返回统一结果包：当前观察版本、变化摘要、证据引用、已完成检查/发现、待调查事项和 finishReadiness。

自动检查只使用已知目标或合法绑定，不代替 Agent 猜测元素语义。动作返回已经包含的新观察不应要求再调用 `page_observe` 才能看见。已有规则结果无需再次 `checks_run`、重新创建假设或重复提交发现。

已完成检查且覆盖账本没有缺项时，给出精简、可校验的收尾建议；有新异常仍可调查。保留 `run_finish` 服务端核验和 Agent 主动提交，不能以隐藏工具强制“提高完成率”。按阶段与能力提供工具说明，明确内置检查不属于声明式 `rule_check`；服务端继续拒绝非法调用。

### 5.2 观察分级与新鲜度

- 轻量观察：读取相关状态、目标连接性、必要几何/命中事实及变化线索。
- 完整观察：进入新页面/状态、变化无法解释、异常取证、首次语义定位、必要检查或明确要求重新观察时执行。
- 复用：仅在本 Run、相同页面与有效事实版本下引用原始观察。返回 `reused`、来源版本和验证依据，不生成假冒的新截图时间。

缓存键必须考虑文档身份、状态版本、视口/滚动、目标身份和相关业务事件；相同 URL、a11y 或文字均不足以复用。DOM MutationObserver 只能作为失效信号之一，不能证明不存在 CSS/动画/canvas 视觉变化；无法验证的场景保守重采集。节点替换、导航、滚动、尺寸变化、相关网络响应或规则依赖变化都应失效。

动作前若必要证据无法证明仍适用，重新取证；先留现场再关闭遮罩。不要把截图、DOM 与 a11y 盲目并发采集成互相矛盾的状态，检测跨版本采集时重采或明确标记不一致。保留 Agent 主动请求全新观察和调查变化的入口。

**验收：** 覆盖文字不变但遮挡/尺寸改变、节点替换、迟到响应、滚动、截图与 DOM 跨状态、恢复后原发现仍存在。相同有效事实重复读取不触发全套采集；变化事实不会被缓存隐藏。新鲜度测试用实际浏览器，时间/取消用确定性时钟或短期限。先跑 P0 四轮诊断，有质量退化则停下修复。

## 6. P2：规则按事实路由与共享检查

文件落点：`src/rules/types.ts`、`engine.ts`、`transition.ts`、`src/execution/rule-binding.ts` 和上下文构建代码。

1. 为规则增加版本化路由元数据：所需页面能力、触发事件类型、依赖事实、执行方式（内置 / 需语义绑定）。旧规则没有元数据时保守走旧评价路径，不默认为不适用。
2. 系统先做确定性筛选，Agent 再处理需要语义判断的候选。规则不适用必须有事实依据；缺少事实应为待补充/unknown，不能被候选数量上限静默丢弃。
3. 模型上下文只携带相关规则摘要、已完成检查及缺失事实。提供分页规则检索/详情工具，摘要有总数和省略说明；一次载入全部声明的行为退出热路径。
4. 检查缓存键至少包含 ruleId/revision、operationId、绑定身份和依赖事实版本。多个规则可共享同一有效观察；时间测量只在观察窗口及目标条件兼容时共享，不能用过期 pass 覆盖新变化。
5. 保留 bound-only 学习规则来源、逐检查证据及去重。普通观察不能再次产生已有绑定检查的重复发现。

**验收：** 用不同数量的合成规则验证无关规则增多不会线性增加默认模型输入；相关规则在分页之外仍可检索、强制适用检查不会漏掉。缺元数据、缺资格、多目标、规则修订、不同操作和缓存失效都有契约测试。私有 fixture 只验证路由机制，不能宣称跨业务语义通过。

## 7. P3：复用有条件的路径片段

文件落点：新增 `src/execution/journeys/`；接入动作执行入口、公开工具契约和既有持久存储。路径数据是声明式受控动作，不运行模型生成的任意代码。

最小路径记录：id/revision、来源 Run/动作/证据、业务范围、前置条件、语义目标与定位依据、逐步动作及后置条件、检查点、允许的写权限、最长动作数/时间、遇到意外的交回条件。来源中的订单号、会话 ID 和旧 elementRef 不得成为新运行的目标身份；每步在当前页面解析并验证。

从成功、有证据的操作轨迹生成候选；没有证据的步骤不能补写。新 Run 只复用路径定义，不复用旧账号会话和业务成功事实。记录来源及候选验证结果；执行授权来自本次 Run 目标与权限，存有路径不等于获准重放写操作。

Agent 可调用拟新增的 `journey_run({ journeyId, revision })`。每次最多连续三个动作，共享当前工具期限和 Run 总预算；服务器验证适用条件、逐步后置条件与证据后执行。段落未结束返回继续位置和实际状态，不能为了执行路径暗中延长单工具期限。

遇到遮罩、目标歧义、状态分叉、未知事实、新质量异常或业务写边界时停止连续执行，先保留证据再交回 Agent。首版涉及下单/支付的写边界必须单独经 Agent 选择现有动作工具；不确定写结果进入原有核对流程，绝不重放整段路径。

回退不是异常分支的固定答案：返回当前状态、已执行动作、停止原因与证据，由 Agent 继续。正常路径仍执行通用检查，Agent 仍有按目标探索未知问题的入口；不能以路径完成冒充范围覆盖。私有变体名称、答案及是否预期失败不得进入路径定义。

**验收：** 正常路径可复用；文案变化、节点换位、同名多按钮、插入新 banner、迟到反馈及写结果未知均安全交回或核对；复用时插入的新缺陷仍能发现。所有子动作计入原动作预算，取消与过期尝试不能继续后续动作。不要只测试“调用了缓存”。

## 8. P4：受控对照与最终放行

### 8.1 执行顺序

1. 各阶段先做相关契约测试；代码稳定后运行 `pnpm format:check`、`pnpm test`、`pnpm build`、`pnpm test:fixtures`。build 已包含 typecheck。
2. P0 建好基线；P1/P2/P3 分别提交，保持单独可关闭/回退的策略。每次先诊断，失败即停止扩大样本。不要仅增加 `maxSteps` 掩盖结果交付或状态丢失。
3. 冻结最终候选和策略后，运行一次真实 DeepSeek/Qwen smoke，通过后跑新诊断：候选 C0–C5 各一次，以及学习规则异常/正常各一次。沿用现有正式 API 和私有评分，学习与未知发现数据库分开。
4. 八例诊断通过后运行 P0 的 A/B M5 十二轮。两组固定同一模型、供应商、目标、视口、初始数据和已批准规则，按配对交替顺序运行，不能用历史 M4 直接充当当日对照。
5. 候选达到质量与性能目标后，使用最终冻结构建重新跑正式 M4 C0–C5 × 3，以及 M5 异常/正常各三次。正式 M4 固定 18 轮不得混入调试样本。A/B 候选六轮若已完整满足相同 M5 契约、配置及记录要求，可以同时引用其 M5 证据，不必重复付费；明确该样本被共用，不称为两批独立验证。

新增诊断入口需复用现有 runner 的隔离、重置、收集和退出逻辑；现有 `experiment:acceptance` 会自带 smoke/六例诊断，调用时列出实际工作量，不隐藏重复费用。每轮立即落盘；退出清理自身服务，失败不杀用户的其他进程。

### 8.2 质量门槛

- 原 M4 固定门槛 18/18；C5 必须在没有等价学习规则时自主发现。
- M5 固定 6/6：异常准确命中、正常无误报，一次完整绑定测量、无重复发现、证据有效、单订单和主动结束均保持。
- 新增观察复用、规则路由和路径回退的确定性门槛全部通过。当前批准规则之外的新泛化声明仍不自动启用。
- 超时、错误和失败必须计入原分母。质量不通过时性能结果只供诊断，不宣称完成优化。

### 8.3 性能目标与统计口径

以下是预先设定的工程目标，不是已有结果或统计显著性承诺：在同等质量门槛下，M5 配对六轮的总模型请求较基线降低至少 20%，总 wall time 降低至少 15%，已知输入加输出 token 总量不增加。另列异常/正常分组、每轮值、中位数与最大值，不能靠一个场景改善掩盖另一个场景退化。

同时报告价格、缓存命中、实际费用、模型等待、工具与测量时间；usage 缺失时费用/token 比较为不完整，不能记成零。六轮不足以证明稳定 p95；不输出伪精确尾延迟结论。任何阈值或协议调整都要另起批次，保留之前结果。

若质量通过但速度目标未达：标为“可靠性通过，性能目标未达”，根据时间分解决定后续；不得扩大总预算、删除困难场景、挑选成功批次或压缩五秒测量。若主要瓶颈仍为上游时延，模型/供应商对照应成为独立实验，不能混入本次代码优化结论。

运行前给出轮数、按当日可用价格/历史用量估计的费用和时间范围，配置批次支出上限；未知价格/用量明确标注。可在发起下一请求前停止超预算批次，但不能保证取消已发出的请求就不再收费。未跑完保留为不完整。不要自动执行完整套件的多次重试。

## 9. 后续 G1/G2：单独证明通用性与视觉发现

P0–P4 通过后再实施，不把这两项算成本轮已有交付。

**G1 业务适配。** 从 `executor.ts` 和 `rule-binding.ts` 提取公开要求、事实解释、业务终态及写权限到明确的适配契约，先原样迁移购物实现。增加一个真实可交互的非购物靶场（例如上传恢复），复用通用 retry 规则；包含允许重试、冷却、次数耗尽、处理中、前置条件不足和多个重试入口。未知协议必须保持 unknown。通用目标条件账本在这里扩展，不用 `paid/rejected` 推广所有业务。至少正常/异常各三轮真实 Agent 验证，与购物结果分开。

**G2 主动视觉检查。** 实施[探索策略文档](../docs/exploration-strategies.md)中的输入区域问题：Qwen 在关键页面主动生成视觉交互范围假设，执行器通过实际点击、焦点变化与坐标变换验证；不只在 DOM 定位失败时调用视觉。靶场包含视觉范围大于可聚焦范围、整块正确转移焦点、合法只读/禁用状态及不同布局。公开任务不告知缺陷位置；分别评价“给定假设能否验证”和“能否自主发现”，正常对照与未知状态不可省略。记录视觉增量请求/耗时，单独做成本与漏检权衡。

暂不包含：流式首 token/idle 协议、分布式 worker、同账号并行写、全站穷举、从业务响应时刻起算的 SLA 改版。这些旧计划中的未实现目标仍未完成，不能因文档整理消失或被标为通过。

## 验证方法

1. 从真实发现关联的测量事实生成声明式候选；只允许既有事件、条件、语义目标和受限状态过滤，不生成任意代码。
2. 新增私有正常恢复对照：同样返回 `status=failed, canRetry=true`，但重试入口可操作。默认 C5 仍不可操作；正常 reset 清除 override。该开关不进入公开变体配置或 Agent 任务。
3. 用浏览器实际操作、trial 点击、命中采样和截图采集正常对照，不能用改写 false 为 true 的方式伪造正常证据。
4. 原始异常测量应 fail、真实正常对照应 pass、缺失事实应 unknown。候选和验证结果展示给人后才可批准。
5. 批准后在独立环境启用，异常和正常各三轮复查；保存全部运行、模型账单、截图与原始测量。检查规则结果、主动结束、单订单约束和证据可用性，并比较探索与复查成本。

模型仍为 DeepSeek + Qwen；固定主模型供应商 Wafer，与已通过 M4 正式批次的实际主模型供应商一致。生成候选最多一次请求、60 秒硬截止，provider 忽略取消也不能无限等待或迟到后写入候选。复查每轮仍为 300 秒 / 30 请求 / 40 动作。不得改写候选以使测试通过；失败保留并明确归因。

## 入口

`pnpm experiment:learning` 的准备模式要求 source、finding 和明确的人工确认原因；准备完成后退出并关闭服务。恢复模式要求原学习目录、精确 proposal ID 和人工 reviewer，仅用于已经得到该候选明确批准后的启用与复查。没有批准不得执行恢复模式。

本流程复用正式反馈、候选生成、验证、审阅、启用与 Run API。正常 fixture 的浏览器采样是私有评估控制，不属于被测 Agent 能力。候选验证不等于启用后复查，也不等于 M5 已通过。

## 验证方法

1. 从真实发现关联的测量事实生成声明式候选；只允许既有事件、条件、语义目标和受限状态过滤，不生成任意代码。
2. 新增私有正常恢复对照：同样返回 `status=failed, canRetry=true`，但重试入口可操作。默认 C5 仍不可操作；正常 reset 清除 override。该开关不进入公开变体配置或 Agent 任务。
3. 用浏览器实际操作、trial 点击、命中采样和截图采集正常对照，不能用改写 false 为 true 的方式伪造正常证据。
4. 原始异常测量应 fail、真实正常对照应 pass、缺失事实应 unknown。候选和验证结果展示给人后才可批准。
5. 批准后在独立环境启用，异常和正常各三轮复查；保存全部运行、模型账单、截图与原始测量。检查规则结果、主动结束、单订单约束和证据可用性，并比较探索与复查成本。

模型仍为 DeepSeek + Qwen；固定主模型供应商 Wafer，与已通过 M4 正式批次的实际主模型供应商一致。生成候选最多一次请求、60 秒硬截止，provider 忽略取消也不能无限等待或迟到后写入候选。复查每轮仍为 300 秒 / 30 请求 / 40 动作。不得改写候选以使测试通过；失败保留并明确归因。

## 入口

`pnpm experiment:learning` 的准备模式要求 source、finding 和明确的人工确认原因；准备完成后退出并关闭服务。恢复模式要求原学习目录、精确 proposal ID 和人工 reviewer，仅用于已经得到该候选明确批准后的启用与复查。没有批准不得执行恢复模式。

本流程复用正式反馈、候选生成、验证、审阅、启用与 Run API。正常 fixture 的浏览器采样是私有评估控制，不属于被测 Agent 能力。候选验证不等于启用后复查，也不等于 M5 已通过。

异常输入返回 fail、缺失事实返回 unknown，均符合预期；真实正常恢复对照返回 unknown，未达到 pass。候选错误地把 `fromState=retrying-disabled` 作为适用条件，将健康恢复排除在外。正常对照的 27 个实际浏览器采样均可操作，不能为了让测试通过而改写其状态。该候选未批准、未启用。

检查实际发出的模型请求发现，结构化输出适配把可选状态字段转成必填字符串，使模型无法省略状态限制。修复生成协议，显式允许 `null` 表示不限制，存储时规范化为字段缺省；同时支持把前一候选及其验证失败作为下一次生成的输入。旧候选和测量事实保持不变，新候选需要重新验证。

修订入口：`pnpm experiment:learning -- --revise <上次学习目录> --previous <失败候选 ID>`。它复制已关闭的学习数据库到新目录，复用已有人工确认，重新采集正常对照并调用真实模型；仍不批准、不启用。

当前计时以 transition 测量开始为原点，不代表已经实现支付响应时刻到入口恢复时刻的完整后台追踪。C5 的持续不可操作事实得到验证，但不能据此宣称任意业务的精确恢复 SLA 已可验证。

## 人工审阅：推广到所有重试类别

用户原文：“我觉得，规则需要再通用一下，不止是重试支付，任何重试类别的按钮，都可以走这条规则。”这是修订范围的要求，不是对先前候选的启用批准。

将规则定义为“重试入口可用性”：来源案例是支付，但规则适用于有业务证据确认当前可重试的任意失败操作。已有事件 `retryable-failure` 与目标 `Retry button` 本身不绑定支付，不需要按业务复制 evaluator。保留可配置的等待窗口，当前候选沿用 5 秒与 error；冷却、次数耗尽、处理中等状态不能仅凭按钮文案被判为可重试。

本轮补充审阅反馈到候选生成 API/实验入口，并保存反馈与前一候选关联。规则层测试包含支付、上传、加载、同步，以及等待窗口、非重试目标、资格不匹配事件。后几类为明确标注的合成契约测试，不冒充真实业务或 Agent 的泛化验收。真实端到端来源目前仍只有支付。

详细适用边界及尚未实现的资格/多目标保障见 [规则库设计](../docs/rules-and-rule-library.md#13-示例跨业务的重试入口可用性)。

首次泛化生成记录：`data/learning/2026-09-23T08-21-00-574Z/`，代码 `ec95fcc`（245 项测试通过）。模型将已记录的语义键 `Retry button` 改成 `Retry control`，被事实匹配校验拒绝，未创建候选、更未启用。一次 Wafer 请求 21.90 秒，输入 2,484 / 输出 3,768 tokens，费用 $0.002606076。失败的模型响应和全部测量仍保留。

这不要求增加一个支付专用规则；需要将已有事实语义键作为生成协议的枚举值，而不是自由文案。修复后模型可修改名称和适用说明，但 target 必须引用已观测语义键，不能为表达泛化而发明新引用。

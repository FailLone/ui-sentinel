# R0 动态页面验证与有界恢复整改计划

2026-10-07；职责为整改开发及自测，独立验收由后续验收者执行。基线 `8b73e3ffa2bf94ce67760c17762ab9dab70c6488`，工作区已有 `docs/product-roadmap.md` 外部修改，保留且不纳入提交。复用第一轮目标失效诊断、摘要、数字校验和评分器修复；不重复实现、不改模型/中性目标/300 秒上限，不引入 R1 探索策略。

## 推荐设计和边界

1. 动作控件保持节点身份绑定；结果测量显式针对动作后当前 DOM。为调查程序增加明确的结果绑定模式及绑定步骤，默认仍为同节点模式。重建 DOM 后不得静默替换旧节点，也不得把原来声明的“同一节点变化”改为“某个新节点符合预期”。
2. UI `page_act.verify` 的预期在动作前固定。执行器保存检查引用、实际动作、原检查事项、动作后观察和页面文档身份；`interaction_verify(checkRef)` 仅重新读取/绑定/测量当前结果，不接受新 selector、预期、证据或 itemId。仅对同文档、无中间动作、干净且可读的原证据和最多两次恢复开放。结果沿原事项追加解决事件；原 unknown/unverified 事件不改写。过期引用、跨任务、错误关联、干预和变化中的测量拒绝，不重放动作。
3. 旧调查的 unknown 仍保留；未经事先声明的结果语义不能通过恢复工具偷换。需要同节点的调查继续保守 unknown。此版本不新增“模型自行宣称两项调查等价”的授权。
4. 防循环沿用现有进度检测和 finalizing 状态：重复内容/同一读取片段不算新进展；到阈值时执行一次有界只读恢复，确有新相关事实时继续；没有新事实则尽早完成 partial 回执，不等待硬超时。健康验收仍要求完整 covered，partial 只证明正确止损。
5. 费用核对独立于产品执行器：原 unknown 行及预留不改写，追加唯一请求的核对记录。来源必须对应已保存 generation ID、固定提供方和模型；查询失败继续保留未知。有效核对参与支出投影一次，幂等重放无双计费、冲突拒绝。费用清楚不恢复已结束批次、不创建批准记录。

## 验证矩阵

| 场景 | 检查方式 | 预期及证据 |
| --- | --- | --- |
| 结果节点被重建 | 真实浏览器调查程序，节点/结果两种模式 | 同节点 unknown；显式动作后绑定 pass/fail；绑定和截图回执 |
| 临时缺失后恢复 | 正式 API，固定模型只提供工具调用 | 原动作一次；第一次 unverified，恢复后原 item verified；历史两次事件均存在；完整终态证明 |
| 永久排序/反馈缺陷 | 正式 API + 独立页面状态检查 | 原 item failed，保留可追溯 finding；仍可完整结束 |
| 错关联/换预期/跨 run | 工具 schema、模块反例及 API 回执 | 拒绝，不清 gap、不产生成功 proof |
| 变化中或干预证据 | DOM 变更、删证据文件、导航/中间动作反例 | unverified/拒绝，不能由重算 hash 绕过 |
| 无新增信息循环 | 固定模型重复读取真实编译服务 | 有界恢复一次，及时 partial；不接受 covered |
| 新事实出现 | 进度单元及真实浏览器 | 仍可调查，不把有效新证据误当循环 |
| 取消与费用缺失 | 费用服务替身及追加 SQLite 投影 | 原 unknown 不变；查询成功幂等结算；失败保留预留；不恢复阶段 |
| 兼容 | 全量 + URL/业务/program 预检 | 老业务写入、取消、未知写入不重放、证据和完成校验不回退 |

A 为单元和真实浏览器边界测试，B 为固定模型正式 API 接线；二者均不证明真实模型自主能力。C 待独立验收冻结并授权，不能由自测替代。保留全部失败和整改前日志。

## 第二轮真实诊断后的修订（83e4be5 → 下一候选）

用户已授权继续直至 R0 完成，并取消 US$2 限制；费用控制及全部 C 出口以 `r0-final-acceptance.md` 为准，以上旧预算建议保留为历史。批次 `r0-ui-diagnostic-83e4be5-02` 六行完整执行，五个 UI 场景未通过、边界场景通过；已知费用 US$0.18321312、未知 0。异常覆盖规则确有发现，但不能替代完成语义。原结果不可修改或拼接。

新增 D6：修复重复观察造成的待检查事项身份断裂。只有执行器比较真实连接中的同一 DOM 节点、相同 URL/类别，且原事项尚为 pending，才允许新观察引用原 item；追加可追踪的重观察记录。相同文字/selector、替换节点、旧 unknown、已完成项均不能据此恢复或覆盖。动作使用当前 ref 仍必须解决原待检查事项。单测及正式 API 证明重复观察后选择/动作/导航归属正确，错误目标和已执行 unknown 保留。

新增 D7：UI 动作前的契约检查。动作后常量断言的独立结果目标须明确 post-action 绑定；需要同节点身份的调查须用前后节点比较或说明身份约束。契约不完整在动作及 hypothesis 创建前拒绝，不能先消费动作再留下无法补证的未知。普通非导航 click/fill 必须预声明后置验证，或放入有测量的调查程序；业务工具语义保持不变。采样上限在动作前检查，并向 Agent 返回当前剩余和已选事项，避免已执行动作因事后选择上限丢失归属。不新增 R1 选择策略，也不扩充时限。

D6/D7 先补 A/B 反例和完整健康流程，再冻结生产候选及新私有保留布局；旧布局进入已见回归。原 unknown 仍只能由原冻结后置契约的有效恢复解决，不能由新成功实验清除。自测与新 C 验收分别记录。

D8（诊断 03 暴露的收尾缺口）：D6/D7 已使真实健康页的已选交互/导航均 verified、调查均 refuted，但模型重复检索历史后，防循环分支直接新增 no-progress gap，导致已满足闭环的运行 partial。修订为：有界只读恢复后，先通过既有 `finishUiScan(scope-covered)` 完整验证器申请完成；仅被拒绝时新增 no-progress 并 partial。不得跳过持久证据、hypothesis、权限或范围校验。另拒绝把 retrieval receipt 当原始 payload 再次嵌套读取，返回原 payload 引用指引；原始历史不改写。增加 covered 后循环应完整结束、unknown 循环仍 partial、引用嵌套不膨胀的 A/B 回归。诊断 03 原失败保留，新候选整批复验，不拼接。

D9（同批 DOM 健康场景发现）：模型把 select 的可见选项名称当作 DOM value，造成健康控件的错误 failed 测量。增加明确 `selected-label-equals` 测量，保留 `value-equals` 的原始值语义；动作前识别“期望值只匹配选项标签、不匹配任何 option.value”的契约歧义，要求修改验证条件后再操作，不自动替换预期。需要非 select、多选、标签错配、原值比较的浏览器反例。独立健康评分也应拒绝 failed 检查项，即使系统未生成 supported finding；这是补严原有健康无误报标准，旧批次不重打分为通过。

D10（诊断 04 的健康对照）：同一下拉框的多次独立测量消耗了三份“控件采样”额度，使其他控件未被触及。检查记录必须独立保存，不能为省额度合并旧 unknown；但采样额度应按每页公开控件标识计数，而不是按 measurement/item 数量计数。执行器以 URL、公开 selector、tag/name/role/href 等可见身份构造只用于额度的 samplingKey；重访同一公开控件不重复占用名额，总动作 20、模型调用 30、300 秒和最多三种公开控件不变。samplingKey 不授予证据归属、不合并事项、不恢复旧 unknown；待检查事项延续仍须真实 DOM 身份。增加三种控件/多次测量可覆盖、第四种仍拒绝、替换节点不继承 pending/unknown 的 A/B 反例。生产指引只强调验证控件公开宣称的效果，不能把无关不变量当核心功能验证，不包含私有控件名或答案。

D11（诊断 04 的已选导航）：模型先选择了页面链接作为待检查事项，之后用纯 URL navigate 绕过该链接；原事项正确留下 navigation-left-target，但健康闭环因此失败。不能用目的 URL 相等就证明原链接可操作。新增 UI 前置提示：当 navigate 的目标对应仍待检查的已选链接时，在离页前拒绝，并要求用该链接的真实 ref 执行 click。无已选链接的直接 URL 导航继续支持；业务行为不变；不会事后消除已有导航 gap。正式 API 验证拒绝时无导航、随后实际 click 完成同一事项；原错误目标/替换节点反例继续通过。

验收工具清理修复（D10/D11 随附）：`evaluation/support/program-replay.ts` 对准备阶段也应用 context finally 清理，增加真实浏览器 setup 失败反例；不修改生产检查、真值或回放预期。两次既有 afterAll 偶发超时根因未获证实，保留原日志，不能把修复明确清理缺口宣称为已证明其根因。

D12（诊断 05，验收方案缺口）：中性目标允许选择页面公开的任一种排序，但旧验收器只接受价格顺序。按名称排序且有实际 GET、正确结果和完整检查证据的健康运行被误判 no-interaction。修订的是判定覆盖的等价公开行为，仍要求实际请求、对应结果、健康完整完成、零误报、真实浏览器健康对照；不接受只观察、unknown 或 partial。新验收器记录请求时间，按快照之前最近一次实际排序请求核对精确列表顺序，拒绝请求/结果不匹配、旧快照和错误页面；独立浏览器同时验证两个公开排序。旧批次评分原样保留，新冻结批次整批复验。

D13（诊断 05，工具契约可用性）：SDK 的严格 JSON 参数可能以 null 表达不适用的可选动作字段；调查 schema 在嵌套 action 联合类型中拒绝这些空值，消耗修复机会。仅把可选字段 null 规范化为缺省，必需的 fill value、scrollY、目标仍须有效；不改变动作预算、绑定要求或写入策略。工具与 schema 明确每个程序最多三次动作、总等待4秒、结果只在最后动作后绑定，建议拆成独立有界问题。不把参数错误算作完成证据，不扩大时限或循环额度。增加正式 SDK 的 null 参数接线与缺失必需动作值反例。

D14（诊断 05，健康误报）：模型从链接标签猜测目的页必须出现同一个词，导航正常却生成 failed 检查。UI 导航契约与目的页内容断言分开：普通链接 click 的导航由执行器根据实际目标/加载证据核验，拒绝夹带局部内容 verify 的导航动作并在派发前指明下一步。先真实导航，再观察目的页，对已知需求另做内容调查；不能从链接文案猜测未见目的页的精确文本。业务路径不变，已有 failed 记录不追改。正式 API 反例证明错误文本预期不派发、不生成误报，随后真实点击同一待检查链接可完成。

D15（诊断 05，无进展恢复）：连续只读后第一次调查调用参数无效，现有防循环立即 partial，未给最新契约错误一次修正机会。保留三轮阈值、一次只读恢复、全部预算与旧 gap；仅当最后一轮确实含 SDK input-validation 错误时，每运行额外允许一次模型修正该契约（不是业务动作重放，也不当成完成/页面新事实）。下一轮仍无新增事实即 partial；普通重复读取没有额外机会。验证修正后真正测量可完成、持续错误只获一次机会并及时 partial。

D16（诊断 06，回执与信息读取）：`page_act` 的 status=completed 只表示派发结束，实际后置验证结果已入账但未回传；模型只能反复寻找历史，遗漏尚待执行的事项。补回动作 ID→原 item 的精简验证回执，并在当前输入中提供最近有证据的动作检查状态；摘要截断仍保留 item/outcome/reasonCode。回执只投影既有执行器账本，不新造通过。UI 的原始证据分片首次读取允许最多三次有界信息访问进展，重复同一分片、空分片、未知 ref、递归读取或仅历史目录均不获进展。此为读取已存在证据的调度额度，不视为新的页面验证、不解除 gap；保留三轮停止机制与全部动作/时间预算。正式 SDK 证明回执对应原 item，首次读取后可执行剩余检查、反复读取仍及时 partial。

D17（同批异常遮挡行）：有效发现已保存，但模型在仍有选中、尚未测量的本页控件时离页，原项正确变为 navigation-left-target，之后无法完整完成。前置守卫在可识别的跨文档 navigate/链接 click 前拒绝离页，要求先处理已选 pending 本页项或诚实结束 partial；不清除旧 gap、不把默认状态当控件已操作。沿用现有路由状态身份（包括 fragment）；未选择控件或旧业务不受影响。页面自行跳转仍按已有 leavePage 记录未完成；首版不承诺跨页复杂业务流程。新增早退被拒、完成本页后真实链接成功的 API/浏览器反例。

D17 核查修订：首个单元反例揭示原方案误把 normalizePageUrl 当作会去除 fragment；源码明确定义 query/fragment 均是路由身份。保留既有路由语义，不修改 normalizer 或 leavePage 来消除 gap。已选 pending 局部检查在路由变化（含 fragment）或显式重载前均先处理；本页检查完成后继续允许这些导航。测试改为验证此更严格的前置限制，健康/异常验收预期不变；保留首次失败日志。

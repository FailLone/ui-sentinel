## 6. 产品场景与实际检查出口

首版支持范围：匿名同源、有公开操作/测量依据的局部 UI 和有界多步路径；不新增登录、外站写入权限。角色上下文记载真实提供的匿名/公开视图状态，不把 UI 的角色名称当权限凭据。所有任务使用中性产品检查目标，模型和通用调度不得读取场景 ID、私有缺陷位置或答案。

拟冻结 12 行产品矩阵（各行是一个具体固定配置，不能运行后选择最有利变体）：

| ID | 场景 | 必须观察到的产品行为 |
| --- | --- | --- |
| C01 | 菜单/折叠健康局部交互 | 实际展开并验证公开后置条件；区分已访问与已验证，零 supported 误报 |

固定免费服务仅用来证明桥接、状态/取消/恢复和评价器正确，复用已有不变量反例；正式产品能力需要真实执行器、真实浏览器、冻结模型与持久证据。每行计数依据实际事件：到底操作了什么、测量是否足够、哪些事项仍未验证、报告和历史读取是否一致。

R1 产品出口（在最终建议交付的策略上独立判定，不从三组挑每行赢家拼接）：C05 两次都产生有效多步调查和可复核发现；C06 两次都无 supported 误报；其余预注册异常子项均按要求发现，健康子项零 supported 误报；所有 verified/failed 条目 100% 有合法操作和测量证据；C10–C12 两次均合法交回/收尾且缺口完整。任一越权、迟到执行、抹除 unknown、伪造完成为硬失败，不能被平均发现率抵消。

## 7. 真实服务、评分和三组实验的有限协议

### S1：具体兼容性小批

开发 Agent 在 S0 后从现有开发输入选定并导出 6 个已见状态：`s01/s03/s05/s07/s17/s21`（菜单、折叠、标签、同文案上下文、信息不足、多步调查交回）。只用公开输入；固定状态 ID 是评价定位，不能进入模型指令。每状态 2 个 eligible 候选、2 维评分及 1 个 readiness 问题，共 5 问题；禁用候选不派发。正式配置路径约定为 `plans/r1-jev-real/smoke-config.json`，目前尚未生成已核准版本。

沿用已提议的 6 次 HTTP、总额最多 US$0.25、每请求 15 秒、总墙钟 5 分钟、并发 1、重试 0、冷缓存。请求模型/实际模型/provider、问题与量表、实际载荷摘要、数量限制、价格日期、最坏费用上界及其来源必须写入冻结记录。金额是上限建议，不能代替报价依据；无法核实费用上界则报告外部缺项，S3/S4 继续，S1 不发送。只补相关协议证据，不反复搜索或安装 SDK 来制造进展。

授权是对具体源码 SHA/配置摘要/6 状态/预算的批准，R0 额度不继承。6 次均有正确归属、可解析结构、实际身份及可核对费用才能称协议验证完成。内容判断错不等同协议失败，留给 S2；非 JSON、错身份、未知费用等按原规则停批。最多一次协议实现纠错后的替代小批，另给授权与原失败；不得删失败补成功。样本总量和已花费用累计保留。

### S2：判断质量

复用现有 24 状态开发集、计分工具和[真实评分子计划](r1-jev-real-adapter-scoring-plan.md)的量表、64 状态/32 家族保留设计、NDCG/交回/注入指标与阈值。先复核作者标签，开发评分最多 24 次、US$0.75；免费重放阈值一次选择，冻结后不再调。独立保留最多 128 次、US$4.00；各批另授权，总体仍按原提议 158 次/US$5.00 上限，不重复发起同一套实验。

S0 修复后，交回与费用指标才能用于出口。保留集在看输出前封存，按家族划分，不使用 R0 私有答案；可由独立评价人员复核，不能把实现者作者标签改名为独立真值。结论分别为满足评分推进门槛、无收益/未达门槛、证据不足；负结果也可“评分实验已结束”，但不能写“评分能力通过”。不为了正结果扩展样本、换模型、换量表、重复收费。

### S5：三组整轮对照，与产品验收共用证据

A 当前 Agent 调度；B 纯程序调度；C 程序加 Jev 调度。三组使用同一统一执行器、观察器、检查/报告规则与允许策略，差异只在常规探索调度。A 保留冻结的当前 Agent 提示与逐步决策循环，不能在看到对照结果后改写 A 的提示制造落后基线。B/C 遇复杂情况可交回同版本主 Agent，交回后的所有调用/耗时/费用必须算进本组；不能把 B 的调用默认为零，也不能让 C 每步仍调用完整主模型再额外加 Jev。

冻结 12 场景 × 3 组 × 2 轮＝72 次整轮运行，一次完整批次，共用第 6 节产品判定；按预定顺序交错组别，页面、数据、浏览器会话、证据与费用账本独立复位，禁止跨组热缓存。重复轮用于稳定性观察，不当成独立场景数量。中性任务、异常/健康配置、公开预期、预算、模型参数、允许恢复、成功谓词、评分代码和样本/源码摘要在运行前冻结。

每个场景冻结 `maxActions/maxNavigations/maxMainCalls/maxJevCalls/maxRecoveries/maxWallMs/maxTotalCostUsd` 及统一的总资源上限：A 的 Jev 次数为 0；B/C 主模型上限与 A 相同；Jev 请求必须占 C 的同一总时间/费用额度，不能额外获赠预算。C12 专门低预算、其余行固定公共上限；不得因某组失败而临时加时/加钱。主模型/视觉模型价格、实际调用上界及接口冻结前，不能虚构整轮美元数；开发交付须给出逐行最坏费用表与72次总上界，批准后才运行。没有该表即“未具备运行条件”，不以旧 US$5 授权覆盖整轮模型费用。

指标同时保留逐行、逐轮和组汇总：独立确认且去重的有效发现/机会数、健康误报及异常漏报；访问状态和实测检查覆盖分别统计；恢复失败/交回/预算耗尽/未运行；实际主模型调用数、Jev及其他模型调用、整轮墙钟和总费用（含初始化、常规循环、交回、失败、恢复和重试）。未知费用单列，不能报完整节省率；整轮失败留在分母。只对冻结真值范围计算召回，不称全站真实召回。

产品硬出口按第 6 节逐项判断；Jev 默认启用收益门槛另判。预注册建议：C 对 A 的有效发现召回与实测覆盖下降均不超过 5 个百分点；健康 supported 误报不增加，关键多步缺陷不得新增漏报；主模型调用总数至少减少 30%，总费用至少减少 20%，总墙钟至少减少 10%。同时报告 B 对 A、C 对 B 的同类差值：若 B 同样满足产品出口且比 C 更便宜/更快，就不宣称收益来自 Jev，也不默认启用 C。C 相对 B 至少要提高有效发现/实测覆盖之一（不牺牲硬出口），或在等质情况下再降低总费用或总墙钟至少 10%。数字为待批前冻结的产品决策门槛，不是已达成绩。

按场景家族给配对差值和区间，重复轮先在场景内汇总；少量场景不支持广泛泛化或强显著性结论。点估计合格但不稳定时最多建议限定范围 opt-in，不能借无限重复把不确定性洗成正结果。不得事后换参考组、挑场景赢家或只算成功请求费用。

若 C 无收益：记录负结论，停止本轮 Jev 调优，选产品出口合格的 A/B 策略；R1 仍可据完整探索能力及产品出口结案，Jev 保持关闭。若 S1 无法兼容或 S2 已有明确负结果而不宜进入 C 的动作实验：停止 Jev 路线、第三组标“未运行及原因”，继续完成 A/B 的探索能力；不能把两组改名三组或自动豁免当前约定出口。由用户/维护者明确裁定是否以非 Jev 方案关闭 R1 范围，未裁定前只声明探索能力/实验负结果，不声明本计划全部阶段验收完成。

## 8. 停止、整改和证据归属

每批报告归类：实现缺陷、评价方案缺口、材料不完整、环境问题、模型质量负结果、统计不确定。前四类明确最小整改与归属；后两类不是自动返工指令。验收 Agent 不直接改实现，不降低门槛，不要求开发 Agent 反复猜题。

S0 最多一次定向开发交付与一次整改；S1 最多一个原小批加一个纠错批；S2 一次开发评分和一次冻结保留实验，无收益即停；S5 一次72行完整对照。若真实产品不变量失败，只修明确根因，追加受影响行的诊断，不能把局部通过拼回原批的“全部通过”。改变共享语义需要新冻结时，先提交范围/费用/旧证据复用判断，由用户决定是否开启另一验收批次，而非自动循环。

证据一律绑定代码与配置 SHA，使用本地相对路径索引及 SHA-256，不重新制作压缩包。既有材料按原 SHA 引用；新材料只收集变更/疑点所需日志、原始响应、派发/账本事件、实际动作/观察/测量及报告。任何验证不得依赖开发机器临时绝对路径、未传递 data 或真实会话资料。缺文件即交付不完整，不能猜内容。

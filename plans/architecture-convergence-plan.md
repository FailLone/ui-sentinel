# 架构选择的持续验证计划

日期：2026-09-24。状态：执行中。用户目标是通过证据找到更优架构或证明当前选择有充分依据；不能以“没有合格候选”结束这项新目标。前轮记录保留在 [决策效率结果](./agent-decision-efficiency-results.md)。

## 什么证据能支持结论

优先保证完整检查质量、未知发现、证据真实性、主动结束和单次业务写入，再比较实际请求、全部费用和报告可用时间。模型/供应商固定的对照与模型推理配置实验分开归因；工具数量、框架名称、理论并行不能代替实测。所有失败保留，不能以更快的失败算收益。

不可能穷举一切未来架构并证明永久全局最优。最终必须交付可复核的架构选择、排除主要备选方案的证据、适用范围和仍可能推翻结论的条件；未经独立复验和陌生场景验证，不称为最优选择。若得到阴性结果，继续根据新证据改变候选方向，不能只重复运行同一矩阵。

## A：修正评估协议，保留历史成绩

新增独立 `recovery-v2` 实验评分，不修改历史 minimum 评分及已发布成绩：

- C2 的 UX 指针拦截发现仍必须有命中采样与截图。业务可以是零订单阻断，或通过正常用户操作恢复后的一笔 paid 订单，且 UI 和报告中的结果一致；正常键盘恢复不是缺陷消失。强制点击、修改页面代码仍禁止，执行轨迹另外核查。
- C5 要求实际 `element-actionable` 连续测量，不能拿可见性测量作证；其引用页面必须包含同一订单，公开响应明确 failed/canRetry=true。其余时间窗口、目标、假设、证据标准保留。
- 新协议所有场景要求显式接受结束。错误或超时退出不能算检查完成；unknown、未验证范围与 supported 发现严格区分。
- 先用反例测试检验新协议；旧九轮只做标明协议版本的离线复评，用于解释局限，不作为新候选独立验收。

## B：拆分模型推理配置与执行循环

旧关闭推理实验只有一个决策状态的一次请求，不能推出端到端质量。先实测六个完整配置：

| 组 | 循环 | DeepSeek 推理 | 其他变化 |
| --- | --- | --- | --- |
| current-low | 当前执行器 | low | 同期基线 |
| current-off | 当前执行器 | disabled | 只改模型推理配置 |
| stagehand-low | Stagehand 3.7.3 | low | 新口径下的既有合格候选，同期复验 |
| stagehand-off | Stagehand 3.7.3 | disabled | 原生循环与共享检查工具 |
| browser-use-off | Browser Use 0.13.10 | disabled | 原生完整输出协议 |
| browser-use-flash | Browser Use 0.13.10 | disabled | 另启用原生 flash_mode，减少 Agent 输出字段 |

官方依据：[OpenRouter reasoning](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens)、[Browser Use 参数](https://docs.browser-use.com/open-source/customize/agent/all-parameters)。flash_mode 精简框架输出字段，与供应商 reasoning 开关不是同一层；实际用量验证开关是否生效。保留 Qwen 按需视觉定位，不启用旧的质量不合格后台视觉巡检。

首批 C0/C2/C5 × 六组，共十八轮筛选（不是正式 minimum 十八轮），按场景循环移动组顺序。每轮 300s、30 个实际上游请求、40 动作，每请求 60s/4096 输出，批次费用硬上限 $3。使用新鲜隔离数据库、同一规则集合、同一任务和视口，不加载 C5 学习规则。禁止为了通过而修改业务、灌入 case ID/答案或增加预算。

每批执行前冻结提交、构建/依赖/评分哈希、模型价格与提供方、顺序和停止条件。正常质量失败继续安全样本；泄漏、重复写入、证据错配立即停止。真实模型失败与明确接线缺陷分开；修复需要新提交、新批次，最多一次同规模纠正，不拼接成绩。运行记录、语义审核与配置依赖均保留。

首批 `851b226` 已因跨轮 journey 记忆污染中止，原生刷新计时也发现误报。唯一修正批次采用每轮独立数据库/服务进程和付费前输入校验，明确测量冷启动而非暖缓存收益；详见 [本轮结果](./architecture-convergence-results.md)。学习复用的价值需要另外安排同等先验的对照，不能混入本轮模型配置收益。

首批仅排除不合格配置，不宣布架构胜出。若关闭推理只改善简单操作却损害调查，则考虑按任务状态选择推理模式，并将升级条件和升级成本作为架构的一部分独立验证；不能简单全局关闭。

## C：根据结果验证必要的架构改动

至少审查下列备选，按新证据排序实施，不同时混入多个改动后宣称单一原因：

1. 当前单操作者与类型化工具，采用合格模型配置。
2. 分层决策：快速浏览操作与显式调查/验证状态；证据决定哪些结论可提交，Agent 决定新假设、语义绑定、合法恢复和结束。必须保持未知探索，不能把答案硬编码为 C2/C5 脚本。
3. 开源原生循环的合格配置；必要时改善工具接入错误恢复，但所有嵌套模型调用和上下文都计费。
4. 仅针对独立且质量已证实的工作尝试并行。共享活页面和业务写操作保持唯一所有者；连续采样不得被并发操作污染。

若单请求不收敛，优先检查事实/任务/结束语义冲突及输出契约，不能仅增加上下文。若请求主要是必要的因果步骤，区分模型等待与框架开销，再决定是否改循环或执行技术。每个新候选先有可证伪预测和安全测试，再冻结小规模诊断；独立失败达到预算后更换假设，不无限调同一提示词。

## D：独立复验、陌生场景与产品验证

候选必须在新批次覆盖完整 C0–C5、健康负例和至少一个未用于调参的业务/布局变化场景；验证的是可迁移机制，不能只在三例靶场找到捷径。新缺陷的判定依据来自公开要求，私有 oracle 只在外部评分。

独立复验至少三次交替重复，比较质量、误报、实际请求、完整费用和分场景时间；另检查上下文体积随步骤的增长和高成本长尾。合格候选优先以相同质量下 >=15% 的时间改进且费用/请求不增加作为采用依据；若质量显著提升但存在成本取舍，明确报告而不伪装满足原门槛。不能以少量重复声称统计 P95。

只有通过独立质量验证后才替换默认路径，并保留回退、相关契约测试、构建/格式、真实 smoke、正式 minimum 和受影响学习复查。架构选择要说明各层职责、语义判断边界、预算/取消/状态隔离、证据与日志、扩展和并行条件。

## C1：先验证能力与调查生命周期契约

依据 B 的重复调查、已解决状态未收敛、finalizing 暴露不可执行工具现象，冻结一个独立接口候选 `capability-lifecycle-1`：只用本次已交付输入计算调查状态（未见完整测量 / 已测量待解释 / 已解决），保留所有原始事实与历史；移除无可用旅程、无未解决假设等无合法参数的工具及 finalizing 运行时禁止的工具，给既有假设和当前元素引用加入 schema 枚举。新假设、检索、合理追加测量仍可用；不输出“应该结束”的程序判定，也不强制只留 finish。

这是一个决策接口包的整体比较，不单独归因于某个字段或工具枚举。旧追加摘要实验不复跑。先执行 `pnpm exec tsx scripts/experiments/decision-replay.ts --study capabilities`：从 B 修正批次选取 current-low 的 C0/1、C2/4、C2/8、C5/7、C5/9、C5/10 六个冻结状态，每状态两组交替各两次，共 24 次实际请求，无浏览器/工具执行。固定同一模型/提供方、low 推理、60s/4096 输出、无重试，费用上限 $0.75。完整保存失败，不单独补跑。

测试保证原输入/系统约束不被修改、完整测量不是自动语义判定、可见性不冒充可操作性、没有旧测量时不凭空生成“已验证”、新问题与已有未知规则仍可检索、已解决/未触发假设不冒充待验证。运行前冻结提交及输入哈希。语义人工复核按清单中的进展标准；工具名合法或主动结束并不自动通过。

## C2：由执行层完成有类型的单次调查

候选开关 `EXECUTION_ATOMIC_INVESTIGATION=1` 默认关闭。相同操作代次、同一实际 DOM 节点、同一条件/窗口、可复用页面版本才返回原调查和原时间窗口；变动、新操作或明确 freshWindowReason 才新测量。复用只证明旧窗口，不伪装刚刚测量。目标消失/替换、空值、窗口不全或取消不能生成支持性结论。报告由执行层生成有限窗口事实，不能声称永远不可用、点击业务一定无效或证明像素遮盖。窗口从测量开始；不假装补测事件发生后已经流逝的前五秒。

## D2：陌生预约页面与健康恢复反例

使用独立的 Workshop reservation 页面，入口、步骤、左右布局与按钮文案都不同于购物靶场；新增明确的勾选前置条件。三个私有配置使用完全相同的公开 HTML，差异来自服务端结果：正常预约成功、处理失败但恢复按钮在五秒内可操作、处理失败且恢复按钮持续不可操作。恢复按钮统一叫 `Resume reservation`，不使用旧 retry 文案正则。业务响应保留当前执行器支持的 success/status/orderId/canRetry 格式；本次验证语义目标与布局迁移，不宣称已经支持任意业务 API。

先验证私有控制口隔离、三个真实浏览器流程、合理禁用前置条件与短暂恢复行为；oracle 反例覆盖错误测量类型、错误按钮/订单、短窗口/稀疏采样/空值、可操作反例、重复发现/写入、缺失证据、未结束和泄漏。健康恢复必须有可见、启用且命中该按钮的页面证据，不能仅凭没有报告缺陷通过。异常恢复必须有同一预约结果下实际恢复控件的五秒连续 actionability 测量、截图、已解决假设和唯一发现。

随后冻结 `--study atomic-holdout`：H0/H1/H2 × baseline/current-atomic × 三次交替重复，共 18 轮，费用硬上限 $2。执行器与模型设置保持 D1 不变，每轮独立数据库/服务、相同规则与公开任务；无学习规则与跨轮 journey。私有配置、验证器答案不进入 Agent 输入。记录 fixture/oracle/构建/依赖哈希，使用正式报告与产物 API。预检不产生付费调用，模型调用数与预算仍为每轮 30 次、40 动作、300s、每请求 60s/4096 输出。

保留所有失败，不按结果调整页面、提示词或预算后拼接成绩。候选要求所有计划轮次通过，无正常状态误报、重复发现、重复业务提交或不主动结束；独立报告分场景时间/调用/费用。若候选不合格，不能凭 D1 的速度收益默认启用，应明确失败机制、保留回退并决定有证据的后续改动。D2 不作为所有网站都适用的证明。

## D3：补齐执行干预的证据边界，再做产品采用决定

D1 暴露了具体反例：基线 C4 第二次提交被执行器拦截，页面因此异常，随后该状态被报告成站点缺陷。候选本批没有重复该错误，不能代替确定性的保护。D2 先保留 D1 构建完成独立迁移验证，不把此修复混入正在运行的对照。

随后用真实浏览器重现这条因果链，在执行器记录网络/策略干预及其时序，将干预后的证据与先前未受干预证据区分开。自动规则、单次调查、旧调查提交和派生证据都必须遵守同一有效性边界；不能只给模型添加一条警告。受干预的观察仍可保存用于复盘，但不能直接升级为未受干预业务的支持性缺陷。以前的有效发现不能因后续干预被删除或降级，已验证业务结果保留来源；新的不确定范围必须出现在最终报告中。

优先明确保守范围，避免伪造可恢复性：在无法证明页面/业务重新独立有效前，不把刷新、滚动、重新读取或换元素当成自动清除干预的依据。正常站点自己返回的失败不是执行器干预，C5/H2 等真实缺陷仍须可发现。未知与失败区分，不通过强制正常 finish 隐藏这类问题，也不解除单次写入约束来换取通过。

验收至少覆盖：真实拦截导致按钮禁用、干预前后的证据不能互换、旧有效发现保留、自动规则和两种未知调查入口都不误报、正常业务失败不被屏蔽，以及最终报告包含来源/未知范围。若修改执行层，补相关契约/浏览器测试、构建/格式、真实 smoke、正式 minimum 和受影响学习复查。最终架构结论同时披露质量与时间代价，不把 D1 的基线失败当作同等质量提速证据。

D3 付费配置：先以本地确定性模型通过编译后 Server/Mastra/Chromium 工具链预检，再使用 `EXECUTION_ATOMIC_INVESTIGATION=1 pnpm experiment:acceptance -- --minimum-only`，固定 DeepSeek/Wafer low 与 Qwen/Alibaba，真实 smoke 后运行完整 C0–C5 × 三次，共 18 轮。美元估算上限 $2，其他预算保持 30 请求/40 动作/300s、每请求 60s/4096；不重复前置六例诊断，不增加预算。保留所有失败，最低通过要求仍使用正式 minimum，不改旧评分；额外审核主动结束、干预来源与有限命题。该发布验收可使用产品正常的导航记忆，不能充当冷启动架构性能对照。

完成后用已有获准且已关闭的学习目录执行 `learning.ts --recheck`，复制同一已启用规则做异常/健康各三次；不替用户确认新发现或批准新规则。验收期间不修改模型、提示词、执行器与预算。是否默认采用以及历史功能保留/回退，在这些记录结束后作最终决定。

D3 原正式批次在 C0-2 出现报告与持久存储不一致；仅两次实际执行，后续十六次未创建。当前先保留失败并诊断，不默认启用候选。局部真实模型诊断和确定性连续重放未复现；同一生产构建的新完整批次附加 SQL 观测，结果不能覆盖原失败。额外补充长期存活 Server、跨轮导航记忆、正式 API 与进程退出后独立 SQLite 读取的一致性预检。详见结果中的 D3 记录。

## D4：区分模型流停滞与决策不收敛，验证有限恢复策略

D3 附加观测批次 16/18，两个 C2 均在已有遮挡证据后连续两次模型请求超时。所有 18 轮的报告与停服后的持久记录一致，但原存储异常仍没有根因；不据新一批通过的部分结果宣称修复。模型超时使当前候选未达到发布门槛。

先修正实验观测：流被取消/中断也保存已收到的事件、responseId 和提供方，分别记录首 reasoning/content/tool 增量及字节量；不保存凭据，不把缺失费用当零，不把收到任何字节视为有效决策。测试截断 JSON、分片 UTF-8、完整流费用、上游错误、下游取消与预算约束；不能通过放宽结束条件消除失败。

随后冻结 `pnpm exec tsx scripts/experiments/decision-replay.ts --study recovery-profiles`：从 D3 选择 C2-2 的第 3/5 个请求、C2-3 的第 4 个请求，以及 C0-1 第 1 个、C5-1 第 4 个、C4-1 第 4 个作为导航、未知发现、健康恢复反例。六份输入及工具 schema 完全不改，low / disabled 交替各一次，共 12 次；固定 DeepSeek/Wafer、60s/4096、无重试、整批 $0.30 上限。没有浏览器或工具执行，case 与评分标准不进入模型输入。所有失败保留，不补跑单个格子。

假设是“在没有执行任何工具的超时之后，改变下一次请求的推理配置，是否比原样重试更容易产生有效决策”，不是全局关闭推理，也不是把低推理当作成功保证。新原子工具契约与暖导航输入不同于 B 的旧循环，因此先验证语义反例，不直接复用 B 的速度结论。人工核查目标/证据/测量条件、未知问题是否继续发现、健康情况不误报、无需再次付款以及合法主动结束。候选必须六个状态均给出有效进展，且原超时状态没有重复空转，才有资格做显式开关下的完整路径恢复诊断；一个状态一次只用于筛选，不是性能证明。

如果失败请求实际一直在输出推理，后续优先验证决策/推理预算与恢复；如果是无输出停滞，才考虑供应商或模型请求竞速。任何竞速只能竞争无副作用的决策结果，胜者选定后才执行工具，所有请求/费用必须计入同一预算；不能对同一浏览器同时执行两个 Agent。没有证据支持时不直接实现并行。任何产品恢复策略变化都重新冻结并完成相关契约测试、正式 minimum 和已有规则复查，默认原子开关继续关闭。

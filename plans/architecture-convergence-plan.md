# 架构选择的持续验证计划

日期：2026-09-24。状态：执行中。用户目标是通过证据找到更优架构或证明当前选择有充分依据；不能以“没有合格候选”结束这项新目标。前轮记录保留在 [决策效率结果](./agent-decision-efficiency-results.md)。

## 什么证据能支持结论

优先保证完整检查质量、未知发现、证据真实性、主动结束和单次业务写入，再比较实际请求、全部费用和报告可用时间。模型/供应商固定的对照与模型推理配置实验分开归因；工具数量、框架名称、理论并行不能代替实测。所有失败保留，不能以更快的失败算收益。

不可能穷举一切未来架构并证明永久全局最优。最终必须交付可复核的架构选择、排除主要备选方案的证据、适用范围和仍可能推翻结论的条件；未经独立复验和陌生场景验证，不称为最优选择。若得到阴性结果，继续根据新证据改变候选方向，不能只重复运行同一矩阵。

## A：修正评估协议，保留历史成绩

新增独立 `recovery-v2` 实验评分，不修改历史 minimum 评分及已发布成绩：

- C2 的 UX 指针拦截发现仍必须有命中采样与截图。业务可以是零订单阻断，或通过正常用户操作恢复后的一笔 paid 订单，且 UI 和报告中的结果一致；正常键盘恢复不是缺陷消失。强制点击、修改页面代码仍禁止，执行轨迹另外核查。
- C5 要求实际 `element-actionable` 连续测量，不能拿可见性测量作证；其引用页面必须包含同一订单，公开响应明确 failed/canRetry=true。其余时间窗口、目标、假设、证据标准保留。
- 新协议所有场景要求显式接受结束。错误或超时退出不能算检查完成；unknown、未验证范围与 supported 发现严格区分。
- 先用反例测试检验新协议；旧九轮只做标明协议版本的离线复评，用于解释局限，不作为新候选独立验收。

## B：拆分模型推理配置与执行循环

旧关闭推理实验只有一个决策状态的一次请求，不能推出端到端质量。先实测六个完整配置：

| 组 | 循环 | DeepSeek 推理 | 其他变化 |
| --- | --- | --- | --- |
| current-low | 当前执行器 | low | 同期基线 |
| current-off | 当前执行器 | disabled | 只改模型推理配置 |
| stagehand-low | Stagehand 3.7.3 | low | 新口径下的既有合格候选，同期复验 |
| stagehand-off | Stagehand 3.7.3 | disabled | 原生循环与共享检查工具 |
| browser-use-off | Browser Use 0.13.10 | disabled | 原生完整输出协议 |
| browser-use-flash | Browser Use 0.13.10 | disabled | 另启用原生 flash_mode，减少 Agent 输出字段 |

官方依据：[OpenRouter reasoning](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens)、[Browser Use 参数](https://docs.browser-use.com/open-source/customize/agent/all-parameters)。flash_mode 精简框架输出字段，与供应商 reasoning 开关不是同一层；实际用量验证开关是否生效。保留 Qwen 按需视觉定位，不启用旧的质量不合格后台视觉巡检。

首批 C0/C2/C5 × 六组，共十八轮筛选（不是正式 minimum 十八轮），按场景循环移动组顺序。每轮 300s、30 个实际上游请求、40 动作，每请求 60s/4096 输出，批次费用硬上限 $3。使用新鲜隔离数据库、同一规则集合、同一任务和视口，不加载 C5 学习规则。禁止为了通过而修改业务、灌入 case ID/答案或增加预算。

每批执行前冻结提交、构建/依赖/评分哈希、模型价格与提供方、顺序和停止条件。正常质量失败继续安全样本；泄漏、重复写入、证据错配立即停止。真实模型失败与明确接线缺陷分开；修复需要新提交、新批次，最多一次同规模纠正，不拼接成绩。运行记录、语义审核与配置依赖均保留。

首批 `851b226` 已因跨轮 journey 记忆污染中止，原生刷新计时也发现误报。唯一修正批次采用每轮独立数据库/服务进程和付费前输入校验，明确测量冷启动而非暖缓存收益；详见 [本轮结果](./architecture-convergence-results.md)。学习复用的价值需要另外安排同等先验的对照，不能混入本轮模型配置收益。

首批仅排除不合格配置，不宣布架构胜出。若关闭推理只改善简单操作却损害调查，则考虑按任务状态选择推理模式，并将升级条件和升级成本作为架构的一部分独立验证；不能简单全局关闭。

## C：根据结果验证必要的架构改动

至少审查下列备选，按新证据排序实施，不同时混入多个改动后宣称单一原因：

1. 当前单操作者与类型化工具，采用合格模型配置。
2. 分层决策：快速浏览操作与显式调查/验证状态；证据决定哪些结论可提交，Agent 决定新假设、语义绑定、合法恢复和结束。必须保持未知探索，不能把答案硬编码为 C2/C5 脚本。
3. 开源原生循环的合格配置；必要时改善工具接入错误恢复，但所有嵌套模型调用和上下文都计费。
4. 仅针对独立且质量已证实的工作尝试并行。共享活页面和业务写操作保持唯一所有者；连续采样不得被并发操作污染。

若单请求不收敛，优先检查事实/任务/结束语义冲突及输出契约，不能仅增加上下文。若请求主要是必要的因果步骤，区分模型等待与框架开销，再决定是否改循环或执行技术。每个新候选先有可证伪预测和安全测试，再冻结小规模诊断；独立失败达到预算后更换假设，不无限调同一提示词。

## D：独立复验、陌生场景与产品验证

候选必须在新批次覆盖完整 C0–C5、健康负例和至少一个未用于调参的业务/布局变化场景；验证的是可迁移机制，不能只在三例靶场找到捷径。新缺陷的判定依据来自公开要求，私有 oracle 只在外部评分。

独立复验至少三次交替重复，比较质量、误报、实际请求、完整费用和分场景时间；另检查上下文体积随步骤的增长和高成本长尾。合格候选优先以相同质量下 >=15% 的时间改进且费用/请求不增加作为采用依据；若质量显著提升但存在成本取舍，明确报告而不伪装满足原门槛。不能以少量重复声称统计 P95。

只有通过独立质量验证后才替换默认路径，并保留回退、相关契约测试、构建/格式、真实 smoke、正式 minimum 和受影响学习复查。架构选择要说明各层职责、语义判断边界、预算/取消/状态隔离、证据与日志、扩展和并行条件。

## C1：先验证能力与调查生命周期契约

依据 B 的重复调查、已解决状态未收敛、finalizing 暴露不可执行工具现象，冻结一个独立接口候选 `capability-lifecycle-1`：只用本次已交付输入计算调查状态（未见完整测量 / 已测量待解释 / 已解决），保留所有原始事实与历史；移除无可用旅程、无未解决假设等无合法参数的工具及 finalizing 运行时禁止的工具，给既有假设和当前元素引用加入 schema 枚举。新假设、检索、合理追加测量仍可用；不输出“应该结束”的程序判定，也不强制只留 finish。

这是一个决策接口包的整体比较，不单独归因于某个字段或工具枚举。旧追加摘要实验不复跑。先执行 `pnpm exec tsx scripts/experiments/decision-replay.ts --study capabilities`：从 B 修正批次选取 current-low 的 C0/1、C2/4、C2/8、C5/7、C5/9、C5/10 六个冻结状态，每状态两组交替各两次，共 24 次实际请求，无浏览器/工具执行。固定同一模型/提供方、low 推理、60s/4096 输出、无重试，费用上限 $0.75。完整保存失败，不单独补跑。

测试保证原输入/系统约束不被修改、完整测量不是自动语义判定、可见性不冒充可操作性、没有旧测量时不凭空生成“已验证”、新问题与已有未知规则仍可检索、已解决/未触发假设不冒充待验证。运行前冻结提交及输入哈希。语义人工复核按清单中的进展标准；工具名合法或主动结束并不自动通过。

候选进入完整路径验证的门槛：12/12 决策语义有效、无质量/副作用/证据退化；相对同期基线请求相同且总时延至少下降 15%、完整费用不增加。若基线有无效决策而候选完整通过，可作为质量提升候选进入诊断，但需披露时延/费用取舍，不宣布提速采用。没有合格候选则结束该接口分支，改用新的证据假设；不能把本次单步重放当成端到端或陌生场景验收。

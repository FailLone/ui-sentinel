## 1. 目标、基线与边界

验证两件独立的事：真实 Jev 服务能否可靠接入已有决策契约；在给定公开页面状态下，Jev 候选评分是否给程序排序带来可测的语义价值。先做“候选评分、程序排序”，不做 Jev 直接操作页面。

产品方向是让 Jev 从少数阻断收尾判断扩展到高频探索决策，逐步让程序连续完成常规交互，必要时交回主 Agent。主 Agent 保留方向检查、复杂语义、多步调查及生成新调查程序的职责。未来必须对照当前 Agent、纯程序、程序加 Jev，比较发现质量、覆盖、主模型调用减少量、总时间和总成本；当前方向尚未证明收益。

## 2. 已有能力与本期缺口

已有纯模块位于 `src/agent/decisions/exploration/`：版本化输入输出、公开状态投影、确定性排序、回执绑定、会话预算、相关状态缓存和交回；开发工具位于 `scripts/r1-jev/`。现有 22 个开发种子及固定回执只证明接线与防御逻辑。

需要补齐的真实差异：

1. 当前 `prompt.ts` 提供 `{system, body}`，真实服务使用 `state + questions`。不能把旧文本当成聊天接口请求，也不能把 `parseStubReply` 当成提供方协议。
2. 现有 `requestDigest` 覆盖纯模块载荷，不包括真实 HTTP 封装；必须另记录完整线上载荷摘要、字节数和问题映射。
3. `TransportIdentity`、`bindReceipt` 和迟到费用回调可复用，但适配器自己必须保证并发请求不会串线；不能给任意响应重新贴当前请求标签。
4. 现有账本约束单会话，不承担跨进程批次费用持久化；需要独立实验账本。
5. 缓存已有状态与适配器身份维度；量表、归一化和服务配置变化必须体现在版本/摘要中。
6. 现有静态无网络检查覆盖纯模块和离线脚本；真实传输放在显式的新边界，不能关闭全局检查或靠文件扩展名绕过检查。

## 3. 提供方依据与待确认事项

以下是 2026-10-07 阅读公开一手资料的结果，不是真实调用证据。

- OpenRouter 的 [Decisions API](https://openrouter.ai/docs/api/api-reference/alphadecisions/submit-a-decisions-request) 定义 `POST /api/alpha/decisions`，请求含 `model/state/questions`，示例回执含问题答案、请求 ID、模型、提供方及 usage/cost。示例模型为 `typesafe/jev-1.13-20260917`、提供方为 `TypeSafe`。本期实现以该入口的协议为准。
- TypeSafe 的 [API 参考](https://docs.typesafe.ai/api) 描述 `score` 的有序量表、加权分数、等级概率、legend 和 confidence；量表支持 2–10 级。本计划选择四级量表，是项目设计，不是提供方质量承诺。直连接口文档只辅助解释语义，不能替代 OpenRouter 的费用及身份契约。
- [OpenRouter Jev 教程](https://openrouter.ai/blog/tutorials/how-to-use-jev/) 说明可在同一状态上提出多个问题；问题 ID 用于代码关联，不能代替问题本身说明评分对象。confidence 反映分布形态，不代表本领域准确率；本期不能照搬教程的阈值。
- [模型页](https://openrouter.ai/typesafe/jev-1.13) 当日列出输入 $0.042/百万 token、输出 $0/百万 token、32,000 token 上下文。这仅用于预算讨论；字节上限不等于 token 上限，不能据此声称某次请求实际费用。

P0 必须保存简短协议核对记录：字段、边界、来源链接、核对日期及文档与实现差异。尚未确认：多问题数量/长度上限及计费如何累计、可用的最坏费用上界、路由固定字段的实际支持、失败/取消后是否有可核对费用的查询接口。不能凭其他 OpenRouter 接口的行为推定本接口支持。只支持一条已核实的 OpenRouter 路径，不同时开发 TypeSafe 直连或新 SDK。

初始配置建议请求 `typesafe/jev-1.13`，预期响应 `typesafe/jev-1.13-20260917` / `TypeSafe`；这是源码与文档相符的待核实配置。拒绝 latest、静默模型降级和身份不符。身份变化先终止该批，记录后重新冻结，不能自动接受新快照。若不支持请求侧固定快照，要明确“别名请求、响应后核验”的局限。

## 5. 问题构造、归一化和执行边界

### 5.1 评分设计

只给当前 eligible 候选评分。每个候选两个 `score` 问题，加一个全局 `choice` 判断该局部任务是否能由当前候选评分支持：`scoreable`、`insufficient-information`、`requires-agent-investigation`。这是独立判断，不能引用其他问题尚未产生的答案。

| 级别 | relevance：与目标相关程度 | informationGain：公开事实支持的新检查价值 |
| --- | --- | --- |
| 0 | 明确与当前目标无关 | 当前相关状态下已覆盖且无新信息依据 |
| 1 | 弱关联的外围内容 | 可能重复或只有很弱的新信息依据 |
| 2 | 可支持目标的局部检查 | 有具体上下文支持发现尚未观察的局部状态 |
| 3 | 直接服务当前局部任务 | 当前任务所需、未观察且有明确公开线索的新状态 |

信息不足不自动打 0 分，不从评分推出未来实际效果；复杂多步调查不因某按钮分高就变成可自动完成。展开、内容变化、导航可以共存。几何只作公开上下文，不成为缺陷标签。主任务文本与页面文本分字段，页面内容只进入数据，不能拼进可信 instructions/criteria。

使用本地生成的候选索引构造问题名和 JSON 字段引用；保留 `questionId -> candidateId + dimension` 映射。不要把任意候选 ID 拼成可解释的指令。无候选、过期/禁用或确定性范围问题先由程序处理，零模型调用。默认一次 HTTP 包含全部问题（最多 32 个候选、65 个问题），P0 核实能否支持；超出已验证数量或体积就明确交回，不静默拆批、截断或漏候选。质量样本每状态 2–8 个 eligible 候选；32 候选边界可先用免费协议测试验证。

分数按四级量表的期望值除以 3 归一到 [0,1]。完整保存原始概率、legend、confidence；uncertainty 定义为两个维度归一化熵 `-sum(p*ln(p))/ln(4)` 的较大值，0*ln(0) 按 0 处理。它只是分布离散程度，不是校准后的错误概率。该计算及全局 choice 交回阈值必须版本化。

全局 choice 必须返回合法类别；非 scoreable 一律交回。初始 confidence 门槛不拍脑袋作为准确率保证：P3 仅在开发集缓存回执上选一次门槛，要求交回召回优先且正常样本保留足够建议；若无可行门槛则停止，不进入 P4。同一开发回执可免费重放门槛，不因此增加模型请求。不得用保留集挑阈值。

### 5.2 绑定与校验

真实适配器是可信边界：捕获不可变输入、每次映射、身份、attemptId、原 requestDigest、完整 wireDigest；一次调用的响应只能经该调用闭包归一化并绑定。用乱序并发、相同候选 ID/不同任务或状态的交叉响应测试它，不能只测试核心信封。

严格核对问题集合、类型、每级概率/legend、有限数值、范围、概率和、加权分数一致性及真实模型/提供方。P0 冻结数值舍入容差（建议概率和 0.025；分数一致性按同一误差上界计算），不通过则整批拒绝；不能用补 0 或重归一化掩盖缺字段/明显无效值。仅对全部校验合格、和在容差内的概率作除以实际总和的数值归一，再计算期望值与熵；保留原始值及数值处理版本，不让熵超出 [0,1]。原始 JSON 重复键也必须拒绝，不能依赖 JSON.parse 覆盖后的值证明唯一性。只把合法使用量作为费用证据，评分失败不抹掉已发生费用。

纯模块的本地请求摘要与线上摘要都保留。问题模板、量表、映射/归一化算法、端点配置摘要合成适配 profile 摘要，并进入 adapterRevision/缓存身份。语义变化同步更新必要的 prompt/result 版本与校验，不让新语义沿用旧缓存。消费前继续校验完整 currentInput；服务不回显观察版本也不能省掉本地绑定。

### 5.3 网络与生命周期

纯决策模块、旧离线命令始终不读取密钥或连接外网。新 CLI 显式装配提供方模块，强制 `billableTransport:true` 和真实 identity，禁止默认 stub 身份连外网。密钥只由独立入口读取 `R1_JEV_API_KEY` 后注入；不自动加载 `.env`，不继承 R0 的额度或配置授权，不记录认证头。

实际线上 JSON 的 UTF-8 字节上限取调用方上限与 32768 的较小值，包括问题及所有协议字段；另按已验证的提供方 token/问题限制预检。响应流上限建议 1 MiB，超出立即中止；禁止先无限读取再检查。端点使用冻结的 HTTPS 地址，拒绝重定向，不从页面 URL 生成请求目标。仅在官方确认支持的字段中限制提供方/禁用回退，响应身份仍独立校验。

默认并发 1、自动重试 0；401/402/429/5xx、非 JSON、结构无效、断流、超时、取消、预算耗尽均明确结束当前尝试。调试重试也是新计费尝试，需要剩余额度和新记录，不能覆盖旧失败。连接到读完 body、归一化、返回建议的全过程受 signal/deadline 约束；迟到结果只补记原请求费用，永不复活建议或缓存。

### 6.2 数据与标签

既有 22 种子是回归集，不计入未见质量成绩。新开发集计划 24 状态（至少 12 场景家族），用于量表检查与 P3；其中 6 状态可作兼容性试跑。保留集另建 64 状态、至少 32 家族，每家族 2 个关联状态：48 个可排序状态和 16 个应交回状态。家族/模板整体划分，菜单名称替换、同页前后状态和注入/干净配对不能跨开发与保留集。

每集覆盖菜单、折叠、标签、同文案异上下文、可并存的动作效果线索、状态变化后重查、缺失/歧义/禁用/过期、连续操作、复杂语义交回，以及页面冒充系统指令；中英文各有独立家族。保留集 48 个可排序状态中至少 8 家族为干净/注入配对。另有确定性非法输入回归，不混入合法状态的质量分母。

公开输入只含正常目标、当前候选与已实际观察的历史。评分标签单独存放：每候选两个 0–3 等级、允许并列的首选集合、handoff 类别、仅基于公开事实的理由、家族和分层信息。不要标注“这个未点击控件一定出现某缺陷”作为模型该知道的答案。不要求唯一首选来消除合理歧义。

开发标签可随 Git 提交；保留集由验收侧在量表冻结后独立准备并先封存摘要，标签只由评分进程读取。输入导出器使用字段白名单，模型进程不加载标签或 fixture 名；以标签哨兵测试请求无泄漏。验收后将必要保留材料随本地证据留存供复核，已披露集合随后只作回归。

标签须在看模型输出前完成复核与争议裁定。当前尚无该批样本/标签，也没有已完成的独立标注；不能把同一实现 Agent 自写标签称为独立真值。不自主派发标注 Agent。若无法获得独立复核，只能做开发性诊断，不能宣称 P4 独立评分验收通过。不用 R0 私有验收答案或保留集，不启动付费模型裁判。

## 7. 真实调用冻结、费用与停止规则

下面是提议的上限，不是本次调用授权。R0 的任何费用授权均不适用。开始 P3/P4 前展示源码、配置、样本、报价和预算的具体冻结记录，再取得对应批次授权。

| 批次 | HTTP 尝试上限 | 美元支出上限 | 冷缓存与目的 |
| --- | --- | --- | --- |
| P3a 兼容试跑 | 6 | 0.25 | 开发集 6 状态各一次，核实协议、身份、usage；不判质量 |
| P3b 开发评分 | 24 | 0.75 | 24 状态各一次，可包含上述已见状态；不计入保留成绩 |
| P4 保留验证 | 128 | 4.00 | 64 状态各两次；每轮请求序列预先固定并记录 |
| 合计 | 158 | 5.00 | 未花额度不自动跨批扩充次数；任何重试占本批次数 |

默认每请求 15 秒，P3a/P3b/P4 批次墙钟上限分别 5/10/40 分钟；单并发，无自动重试。到任何一个上限即停止。128 次指重复测量而非 128 个独立场景，不把两次重复当成样本量翻倍。

真实派发前必须有有限、可说明依据的最坏费用预留：核实多问题计费单位、价格快照及上界所覆盖的所有计费项。不能把猜测 token 数、HTTP 字节数或一次试跑均价当最坏报价；无法建立上界时真实阶段阻塞，先做免费开发。上述 $5 是实验总额度建议，不是费用预测，也不能保证提供方永不超收。实际 usage 作为实际支出，报价只作预留，二者分列。价格变更需重新核算并冻结。

独立持久账本在 HTTP 派发前原子写入预留和尝试 ID；同一 campaign 只能一个进程持锁。重启看见 dispatched/pending/unknown 就停止，不自动重发。缺费用、无效费用、取消后未知收费或超报价时全批停止；未知占用不释放，不能开启新会话洗掉不确定性。只有与该请求关联的可信结算能解除占用，后补结算不改变旧建议结果。账本写入失败也不继续发请求。

若服务支持费用核对，P0 先确认接口、身份关联和该查询本身的收费，另冻结查询次数/时限；未证实支持就人工核对并保留 unknown，不猜测，不自动发额外网络请求。账本仅存安全元数据，不保存 key 或真实会话。

冻结清单必须包括：完整源码 SHA、工作区 clean、锁文件/运行时、数据与标签摘要、分组划分、量表/阈值/排名策略/profile 摘要、模型请求 ID 与预期实际身份、端点与协议依据、价格和报价算法、每批次数/金额/时限、重试=0、并发=1、cache=cold、随机种子、指标及授权依据。文件默认 `authorized:false`；presence of key 不构成授权。冻结后任一项语义变化，新建批次，旧失败完整保留。

## 8. 评价与验收判定

### 8.1 可靠性出口

免费矩阵必须全通过；真实协议试跑的全部计划请求必须有可追溯结果，不能将失败删掉再补足成功数。真实回执正确绑定；无效/过期/迟到建议接受数为 0；默认离线外发数为 0。全部已派发请求最终费用可核对才可声明该批成本完整；未知费用意味着证据/结算未完成。当前批次遇停止条件立即停，修复后按新冻结批次处理。

### 8.2 评分指标与门槛

两组都使用同一公开输入、候选、历史和 fairness：纯程序排序，以及程序加真实 Jev。排名策略固定，逐状态配对比较。评分量表本身、融合后排序、交回行为分别报告，避免模型分数有差异却被排序优先级遮蔽而误判收益。

- 主要指标：可排序状态的 NDCG@3，标签 utility=`0.6*r + 0.4*i`，DCG 使用线性 utility/log2(rank+1)，IDCG 同候选排序。样本在封存前应至少有一个正 utility；无正 utility 标为应交回，不事后排除难例。handoff/无效响应在可排序状态上的 NDCG 和首选命中均记 0。
- 次要指标：首选落在预标注可接受集合的比例；两维评分归一化 MAE；交回召回/误交回；无效响应比例；两次测量的首选一致率及最大分数变化；按菜单/标签/中文/注入等分层给出原始数。
- 延迟记录单请求及批次实际耗时、p50/p95、有效建议数；费用给出已知总额、未知数量、每有效建议费用，所有失败/交回的费用计入。无有效建议时单价不可定义，不填 0。warm-cache 单列免费重放性能，不掺入真实冷缓存成绩。
- 质量推进门槛：48 个可排序状态按两次结果先求状态均值，再按家族汇总；平均 NDCG@3 比程序基线提高至少 0.05，按家族配对 bootstrap 的 95% 区间下界大于 0；首选命中率至少 80%，应交回状态召回至少 90%，可排序状态误交回不高于 15%。每个指标同时给分子分母。bootstrap 固定种子 20261007、10,000 次，不把同家族或同状态重复当独立样本。
- 注入配对：不能产生越权输出；注入不得使原应交回状态变为有效自动建议；干净/注入配对的可接受首选命中率差下降不超过 10 个百分点。报告样本很小及区间，不能据此宣称通用抗注入能力。

以上数值是本计划建议的进入下一步实验门槛，不是现有成绩。P3 可暴露天花板、标签歧义或样本不足；如确需变更评价协议，应在任何保留结果出现前给出理由并新版本冻结。不得看 P4 结果后降门槛。置信区间太宽则“证据不足”，不因点估计好看而通过；本计划不自动追加付费样本。

结论分层：协议通过但质量无增益，保留适配实现、暂不集成调度；协议失败，修实现；标签/样本或费用材料不足，标记证据不足；可靠性和质量均满足门槛，只建议进入隔离状态采集/建议旁路记录。不得写“整轮成本已下降”或“R1 已完成”。本期不调用当前主 Agent 作为第三付费评审组；当前 Agent/程序/程序加 Jev 的完整三组对照仍属后续实际执行实验。

## 9. 命令、材料与独立复核

现有环境要求 Node 24.x、pnpm 10.17.1、Git；无需浏览器 profile、R0 数据库或本机未交付资料。已有入口可用于基线检查：

```sh
node --version
pnpm --version
pnpm exec node --version
pnpm install --frozen-lockfile --store-dir .r1-pnpm-store
node plans/r1-jev-input/preflight.mjs
pnpm exec tsc --noEmit
pnpm r1:jev:test
```

本期实现须增加以下专用入口并写入说明（目前不能运行）：

```sh
pnpm r1:jev:real:test
pnpm r1:jev:real -- --dry-run --config <config.json> --output <evidence-dir>
pnpm r1:jev:real -- --run --freeze <freeze.json> --authorization <authorization.json> --output <evidence-dir>
pnpm r1:jev:score -- --evidence <evidence-dir> --labels <labels.json> --output <report-dir>
pnpm r1:jev:verify -- --evidence <evidence-dir>
```

`--dry-run` 不读密钥、不外发，仅生成实际请求、字节/问题计数、报价依据及阻塞原因；`--run` 缺冻结、授权、已知预算、真实身份或费用上界就非零退出。验收后重算使用原始已保存响应，不再调用模型。新干净克隆验证锁定安装和免费测试；不要运行脱敏树缺失的 R0 顶层全套验收命令来冒充本期验证。

每批在本工作区独立 `artifacts/r1-jev-real/<campaign-id>/` 留存：

| 路径 | 必须内容 |
| --- | --- |
| `manifest.json`、`freeze.json` | 源码与配置身份、文件索引/摘要、协议版本、批次及环境；索引不对自身作循环摘要 |
| `inputs/`、`requests/` | 实际公开输入、无认证头的线上请求正文、问题映射、两类 digest；不含标签 |
| `responses/`、`attempts.jsonl` | 有界响应、归一化回执、结果、时序/取消/异常与身份；失败也保留 |
| `ledger.jsonl` | 预留、派发、结算、未知与迟到费用的追加记录 |
| `evaluation/` | 只在评价側保存标签/标签摘要、两组排序、逐状态分数、分层/区间及汇总 |
| `logs/`、`environment.json` | 实际命令、退出码、原始日志、Node/pnpm/工具版本；绝对路径到相对文件的映射 |
| `report.md` | 完成项、偏差、已知限制、所有失败、未完成项、建议与证据相对链接 |

不保存 key、Cookie、真实会话、认证头或任意未筛选错误正文。成功响应来自合成公开输入也要做敏感字段检查；需要脱敏时注明字段和原因，不称脱敏副本为逐字原始证据。错误记录安全字段、状态码、请求 ID 和截断/解析情况；不得借完整日志泄密。附件只保留复核必需文件，不打包整个 data。

本地 Git 提交代码、测试、开发 fixture、锁文件和运行说明；大体积运行证据保持独立目录，以相对路径及 SHA-256 关联。接手者取得对应 commit 和索引覆盖的证据即可复核；没有开发机器路径依赖，不要求再生成压缩包。

独立验收顺序：检查 Git 基线/最终 SHA/工作区状态与允许 diff；核对索引和所有摘要、相对路径与依赖；干净环境重建免费测试；验证原始请求无标签及数据跨集泄漏；离线重算报告；逐条审查真实失败和费用完整性。材料缺失标“交付不完整”；环境问题、实现缺陷、方案缺口、证据不足分别列出，不猜测缺失文件，不改预期制造通过。

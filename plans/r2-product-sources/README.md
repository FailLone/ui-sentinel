# R2：产品资料驱动的一条关键路径

目标：普通用户输入网址，并提供一份文本/Markdown 产品资料；应用提取一条有来源的短关键路径，绑定网页上的真实控件，通过既有执行器操作和测量，最后给出要求与证据对应的报告。不是只增加资料输入框，也不是再做一轮 Jev 收益实验。

## 实现范围

1. 工作台/API 接受可选资料，冻结标题、原文、版本、内容 hash 和引用位置。未提供资料时保留原网址扫描行为。页面内容和资料均为待检查数据，不授予新权限。
2. 主 Agent 使用应用内部版本化 Skill 指引理解资料，区分前置条件、操作步骤、预期结果、未知信息和模型假设。首版选取一条在匿名、现有权限和预算内可执行的短路径；展示选择理由及未选范围，不声称整个 PRD 已验证。
3. 按需提供资料目录/章节概览、关键词搜索、带游标的原文读取，以及要求/路径进度查询。摘要只用于定位，最终结论引用冻结原文。搜索未命中或分页截断不能被当作“没有要求”。首版不引入向量库、独立模型循环或通用 Skill 平台。
4. 在真实页面上绑定目标，复用原动作、generic/effects、调查测量、scope、取消、预算和持久报告。资料保存“应该怎样”，结构化执行状态保存“做了什么、还缺什么”。预期需在动作前有独立依据；不能根据实际结果反填答案，不能为补关联重复点击。
5. 报告明确列出来源要求、原动作与测量证据、缺陷/通过/未验证原因及未检查范围；支持历史恢复。资料更新后依赖的要求与路径需重新核对，旧运行证据保持原版本。
6. Skill 是主 Agent 的工作方法与工具使用指引；Rule 是质量约束及程序判定，脚本复用执行/取证流程。不另建重复的“检查任务库”。现有并发工具可按实际需要复用，不以并发作为本轮完成前提。

## 完成条件

- 工作台和 API 都能走通“网址 + 一份资料 → 路径选择 → 实际执行 → 对照报告 → 历史恢复”。普通用户无需提供 CSS、程序或检查清单。
- 免费确定性浏览器场景至少覆盖：健康路径、与原资料不符的结果、含糊要求、前置条件缺失、来源/证据完整性失效。必要的类型、格式与影响范围回归通过，保留失败证据。
- 所有已登记必需工作和默认采样义务仍受原完成门约束；不能用路径完成绕过其他 pending。无法实现的要求明确未验证；真实模型稳定性与固定模型接线证据分开报告。
- 不扩展 Figma、登录/角色、业务写入、多文档全覆盖、长期记忆、向量检索或新付费实验。无本轮付费授权，不复用历史授权；若免费闭环完成后确需真实模型验收，准备最小、可审查的具体方案再申请。

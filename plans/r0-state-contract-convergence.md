### 唯一的结束决策顺序

这是一张需要执行器、持久校验、报告及验收器共同遵守的决策表，不是按某个测试页面打补丁。

| 可检查事实 | 允许的终态 | 必须保留 / 验证 |
| --- | --- | --- |
| 实际已派发且结果未知的业务写入 | interrupted / reconciliation-required；不可自动重放 | 原动作、请求归属、未确认回执与隔离；取消等并发事实也留档，不能用 partial 消除未知写入 |
| 用户取消 / 预算耗尽，且无未知派发写入 | cancelled / timed-out（既有结束路径） | 原原因及实际未完成范围；迟到回调不得生成完成证明 |
| 经持久事实确认的页面干预，已排除未知写入 | blocked / blocked，partial 或 not-started，业务不适用 | 同一 run、finish 前的有效拒绝/干预依据、未验证范围、持久有效的结束证明；不再依赖模型猜收尾 |
| 干净运行且入口、已选义务、适用规则、hypothesis 与证据全部满足 | completed / goal-reached / not-applicable | 可以有已验证发现；覆盖只限约定范围；完整持久校验不可略过 |

| 模型流截断/执行异常，既无合格结束证明也无未知写入 | execution-error 等实际失败终态 | 不把模型故障虚构成站点 blocker；不能由报告文字包装为成功 partial |

任何自动收尾都须先等待网络决策及相关证据尾队列落库，再检查取消/预算/未知写入、决定结束，最后复用原持久验证器。请求未真正发出必须有可信边界事实；“站点日志没有请求”只是独立测试证据，不能成为生产通用判据。未清楚关联的状态保持保守，不能靠 URL/方法/按钮文字猜测。

## 二、C10 专项根因：为何继续加一个收尾补丁不够

### 原始失败链

边界行运行 `run-5cc36382-2af2-436c-a2fe-25e17b8b0a56`：

1. 页面初始化发出 `/write` POST；UI 边界拒绝，服务端未收到写入。`execution:intervention` 是 seq=12，事件 `evt-4d3595f0-5d0c-4af9-8978-6cc86e5e1f6f`。
2. 实际模型调用两次、页面动作零次。第二次流以 `length` 截断。
3. `execution:stopped` seq=46 明确保存 `error=model-stream-incomplete:length`、`sideEffectPending=true`、`reason=reconciliation-required`。不是只从报告标题推断。
4. 最终 interrupted，无有效 finish，原私有边界分支只检查非 covered、存在干预、无 finding、服务端无 POST，遗漏终态与证明，所以误通过。

源码对应：`executor.ts` 的共享 `page.request/requestfailed` 监听器先把非 GET/HEAD/OPTIONS 请求放入 pendingWrites；业务边界通过 `denyWrite(request)` 消除“未发出却未知”的歧义。UI 使用 CDP/session 拒绝路径，未接入这个同对象标记，requestfailed 仍把拒绝当作未知写入。`canRetry`、异常归因及队列隔离随后读到此标记。这是请求生命周期和业务写入状态混用，模型 length 是触发显现的条件。

另有可重现的相邻缺口：`uiBlockerEvidence()` 把 **所有** `network:decision` 纳入 blocker，包含成功放行的 document。`decideInspectionCompletion(observed-blocker)` 只检查非空列表；`inspectionHistoryIssues()` 对该 claim 没有重新验证真实 blocker。正常静态页仅有允许的 GET，也可被模型以 observed-blocker 结束并得到 proofVerified=true。它没有冒充 covered，但理由不成立，违背“不能靠模型说无法继续就收尾”的契约。

因此撤回此前“加一个 intervention 自动 finish 分支就足够”的初步判断。单独这样做可能绕开并掩盖错误的未知写入标记；必须把请求归属、可信 blocker、收尾和历史验证作为同一条状态转换先讲清、后验证。不扩展成全面重构。

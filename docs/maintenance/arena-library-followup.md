# 靶场维护与持续回溯

[靶场目录](../counterexample-arena.md)是可重复页面的入口，[评估指南](../arena-and-evaluation.md)定义结果边界。维护工作随功能和规则变更进行，不依赖私人会话提醒或单独的靶场项目。

## 何时回溯

提交功能、修复缺陷或扩展规则的人在变更说明中检查：新发现是否已有可执行反例、能否复用现有页族、是否需要健康或 unknown 对照。审阅者核对公开/私有隔离、复位和结果范围。没有新增资产时说明现有覆盖位置，不为交付次数再造页面。

## 如何归属

| 反例类型 | 维护位置与入口 |
| --- | --- |
| 浮层、图片、裁切/遮字的稳定页面机制 | [反例靶场](../counterexample-arena.md)，复用现有 catalog 和页面生成器 |
| 动态后续控件、资料引用、结果/前置条件 | `scripts/validation/product-sources.ts`；资料页族 `evaluation/fixtures/product-sources/` |
| 健康路径复用、目标歧义/缺失、前置失效 | `scripts/validation/path-reuse.ts`，复用同一资料页族 |
| 来源/公开事实变化、未到达状态、历史基线选择 | 同一入口的 `--regression` / `--focused-review`；`scripts/validation/regression-picker.ts` |
| 候选状态、路径、去重与恢复 | `scripts/research/exploration-acceptance/` 与 `src/agent/exploration/` 的定向回归 |
| 取消、迟到结果、费用、网络、证据归属与持久化 | 相应协议单测和集成回归；页面不能证明这些契约 |
| 原报告缺图、缺附件或无法恢复网站 | 保留稳定来源 ID、摘要和缺口，不称原问题已复现 |

## 新增反例流程

1. 从实际问题提炼最小机制，记录适用条件和独立预期。异常、健康、不适用、unknown 分开；正常滚动、裁切、加载或模态背景不自动算缺陷。
2. 优先扩展现有页族。场景选择在服务启动前完成；同一中性 URL，不把 case ID、预期缺陷、私有标签或故障开关传给 Agent。
3. 明确初始状态和复位方法。运行中不热切换变体；并发使用独立进程、端口、浏览器 context 和需要时的独立数据库。
4. 先独立确认页面真值，再调用正式检查器/执行器。区分直接测量、固定回复接线、真实自主选择；不能从前两项推导第三项。
5. 保存失败、截图、源码/构建指纹与摘要，更新目录中的适用范围。原始产物在 `data/`，不随 Git 分发；可移交索引须说明取得方式，未知时明确未知。

每次回溯只运行受影响的验证。复用有效旧证据时写明版本和范围，不拼接成“同一最终构建全部通过”。付费验证另行冻结和授权。

## 当前维护重点

普通网址入口需继续区分合法执行路径与模型自主选择；后续修复合入时补目标解析、待办缺证据、动态入口可达性的对应回归。变化比较应保留初始、实际到达、派发前状态三层；未知执行不重放。资料语义变化后的模型规划、图片保形语义和复杂绘制仍需独立证据，不能用合成页面数替代。

历史真实 D 交回复验依赖封存数据库和固定端口，不是 clone 即可运行的通用靶场。可移植的长期回归应从随 Git 的健康资料新建候选；新生成候选不得冒称历史真实作者证据。见[历史与证据](../archive/README.md)。

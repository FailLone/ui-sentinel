## 范围与接线

工作台按精确入口列出最近历史健康检查，用户显式选择基线并提交本次资料；API 使用 `baselineRunId`。服务端重新验证基线完整报告，经既有 R3 derive/save 生成候选，再冻结原 `pathProgramId` 与基线定位。手填路径 ID 保留为高级入口。历史选择不是权限继承，来源、预算、网络、动作与完成门仍由本次契约决定。

复用原 runs/events/path_programs，不建新数据库、执行器或调度。比较事件记录精确入口/来源身份与版本；每一步在实际到达的状态比较原 sourceReview 页面与本次公开节点。比较粒度为目标、结果、前置的结构及公开文本/值/可见属性；其余公开叶节点变化只称“路径依赖之外的展示变化”，不推断全站或业务兼容。身份和文档计数不是成功证据。观察不完整、缺少历史观察、截断则未知；未进入步骤尚未检查，不能判为缺失。

原 R3 执行器仍分阶段重新观察、唯一绑定、前置复查、操作和测量。结构变化/缺失/歧义沿原门交回，结果不符保留本次真实缺陷。来源变化在安装计划前进入原 R2 资料流程；安装后交回只读，不重放、换计划或暗中创建新运行。报告通过持久比较事件和原产品报告区分历史参考、本次实测、未检查与失效。比较结论不能核销义务。

本轮减少重复路径提取和规划，每个宣称本次通过的步骤仍取得新证据。不做自动部分修订、任意 DOM 迁移、相似度/向量检索、全站扫描、长期记忆、长流程、登录或业务写入。

## 验证计划

## 实际入口

使用 Node 24，安装锁定依赖并构建；启用已有 `EXECUTION_URL_SCAN=1 EXECUTION_PRODUCT_SOURCES=1` 后启动工作台。正常产品初次调查、资料变更或只读交回可能调用已配置主模型；本轮验证专用入口始终使用本地固定回复。

1. 选择“网址 UI 检查”，输入同一精确网址。
2. “沿用历史检查（可选）”自动列出最近 20 个同入口已完成运行中的健康候选，显示路径名称、来源版本、时间及步骤。历史证据缺失或不健康的运行不提供候选。
3. 显式选择一次历史检查，填写**本次**资料名称、版本和正文，开始检查。无需先保存或复制路径 ID；服务端通过原健康门验证后自动保存声明式候选。修改网址会清除选择。
4. 查看“相对历史检查的变化”，区分历史参考、本次新验证、缺陷和未验证；旧步骤失效与新资料调查分开。测量和证据链接仍在原产品报告。高级手填 ID 保留。

`GET /api/regression-baselines?entryUrl=<编码后的完整URL>` 为只读有界候选发现，不访问目标网页、不调用模型；比较当前页面发生在明确开始的新运行内。

```json
{
  "kind": "ui-scan",
  "entryUrl": "https://example.org/catalog",
  "baselineRunId": "run-…",
  "productSource": { "title": "目录说明", "version": "2", "markdown": "本次实际资料全文" }
}
```

提交至原 `POST /api/runs`。`baselineRunId` 不可与手填 `pathProgramId` 同传；缺本次资料、非健康/丢证基线或非精确入口均在创建运行前拒绝，不暗中创建替代运行。基线和生成的路径 ID 一同进入原冻结契约。

## 比较依据与边界

- 精确入口含 query/fragment，来源比较身份、版本、正文摘要；正文相同而版本变化也使旧计划失效。匹配仅允许尝试重新测量。
- 比较历史每一步原 `sourceReview.page` 与本次同一步操作前的公开观察。结构按 R3 目标描述与来源命名唯一性校验；公开事实比较名称、文本、值、可见性和属性。不能根据坐标或相似名称迁移。
- 依赖之外的变化只比较完整公开叶节点。祖先聚合文本常含长脚本或重复子节点内容，明确排除，避免把同一子节点变化重复算作全页变化。实际依赖本身截断、公开采集不完整、历史缺失时记未知，不声称 DOM 全量相等。展示变化最多展开 12 项并给出总数。
- `path-regression:identity`、`path-regression:observed` 保存前后事实、原入口/来源身份、观察摘要和阶段；`uiScan.regression` 从持久事件与原 `productPathReport` 投影。本次 verified/failed 仍依赖原来源、动作、测量和可读证据；证据降级会同时降级增量报告。
- 动态第二步只在第一步后比较。尚未到达、预算不足、取消及未知执行不能反推后续目标缺失或失效。前置不满足、目标变更/歧义沿原门停止；已发生动作后只读交回，没有局部自动换计划。
- 来源变更时旧步骤均为历史参考/本次未验证；动作前可以进入原 R2 资料读取与新计划登记，新计划的结果放原产品报告，不按相同步骤序号冒充旧路径验证。

本轮“增量”是复用有效的声明式短路径、减少重复资料提取/规划/参数拼装；比较帮助定位需要调查的依赖，未实现自动局部修订或减少必需测量。固定回复的请求数差仅证明接线，不是实际模型费用、时延或语义收益。

R4 模式沿同一 R3 验证程序扩展现有 R2 页族，以随 Git 的资料和健康页新建基线，不读取任何历史真实数据库。独立 SQLite、正式构建服务、loopback 固定模型及真实 Chromium；显式拒绝 `--real`。测试中源页面变体由操作员在运行前设定，模型只收到公开页与资料。

候选发现、普通选择、来源变更后的原 R2 调查、未知/取消不重放及报告恢复属于本期长期回归入口；不需要复制靶场或执行器。中央靶场回溯与 Roadmap 留给维护者整合。

真实模型验收不是本次确定性变化比较和历史选择的前置。若下一阶段需要宣称“真实用户资料变化后能正确重新调查”，最小有意义验证是：一个真实作者健康基线＋一次有语义变化资料的重复检查，检查新计划确实依据新资料；需单独授权。本轮没有调用真实模型，没有自动安排新批次，也未重开 R3 模型额外文字说明的验收。

### 其余审阅结论

- 外部 `baselineRunId` 与手填 `pathProgramId` 互斥；服务端解析历史选择后，内部契约同时冻结二者是正常定位，不会再次触发外部互斥。入口按相同 URL 规范化后比较，query/fragment 不被抹去；原地址/匿名策略仍在创建前执行。
- 候选发现是建议列表；创建与再次保存共用 `checkedPathProgram`，重新校验完整健康报告、可读证据和原路径。首次健康运行与一次新复用运行都经本轮附件移除反例：旧报告/增量报告降级、候选排除、创建及再次保存返回 409，恢复附件后报告逐对象恢复。重复健康保存保持幂等，非精确入口和冲突 ID 在创建前拒绝。
- 本轮准入探针前后运行列表、目标网页请求数、模型调用数完全相同，确认查询/拒绝没有暗中创建运行、访问网页或启动模型。没有修改无基线、手填 ID、来源变更后的原资料流程；按影响复用原测试及首轮证据。
- 比较只取每一步实际到达状态。完整性不足/截断/历史缺失仍未知，未到达动态后续仍不判缺失；目标/结果值变化只允许尝试原测量。隐藏实现变化及来源版本变更沿用首轮反例，不把 DOM/来源匹配当成功。
- 新来源的计划不按序号核销旧路径；本次状态由原 `productPathReport` 和证据投影生成，比较事件没有通过权限。本轮附件失效同时使新复用报告的增量步骤降级。取消、未知动作不重放的运行器定向测试通过；原真实浏览器取消/执行错误与 13 份恢复证据按影响复用。
- URL 编辑清空历史选择，失败/空列表不会保持旧候选。异步返回已加失效检查。查询不回填当前资料或手填 ID；用户明确选择历史候选时才清空并禁用手填 ID，避免两种选择同时提交。普通提交流程在本轮再次走通。
- 候选验证每请求最多 20 个完成运行，有 300ms 输入去抖；没有发现此范围内需要新增框架的无界网页/模型工作。SQLite 筛选本身仍可能随历史表规模增长，20 个候选不等于数据库扫描常数成本；保留规模性能限制，不新增索引/缓存系统或大历史性能承诺。

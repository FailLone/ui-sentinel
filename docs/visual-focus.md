# 视觉发现与聚焦验证

当前能力验证“看起来像输入区域，但部分内部点击不能聚焦”的问题。`EXECUTION_VISUAL_DISCOVERY=1` 显式开启，默认关闭。它是输入区域专用快捷路径；其他问题可使用[可组合调查](composable-investigations.md)，两者共用执行预算、证据与报告。

## 发现与绑定

执行器在首次稳定观察后、常规 Agent 决策前进行有界视觉扫描。Qwen 读取真实视口截图和公开任务，提出视觉输入区域；不接收 DOM 实际输入宽度、私有答案或建议点击点。扫描在执行循环内完成，不是后台浏览器控制线程。

单次最多两个候选，每个候选最多四个排除区域。候选类型为 `input-focus-region`，包含外观区域、可见语义、视觉依据及置信度；候选不是缺陷结论。模型输出采用显式 normalized-1000 坐标，服务器按已验证视口转换为 CSS 像素，保留原响应与转换依据；非法或越界框整体拒绝，不猜测单位或裁剪成合法框。

每个 run 最多两次扫描，第二次只用于第一次采集在请求期间失效后的重采。所有视觉请求计入共享模型次数与时限。没有稳定图像、模型失败或再次失效时保留未验证范围；空候选也不能证明页面没有问题。

主 Agent 决定是否调用 `focus_probe({candidateId, elementRef, bindingReason})`，将候选绑定到当前唯一、可见可编辑的原生输入节点。该工具不接受任意点击坐标、selector 或模型自报的结果。执行器验证 run、截图、文档、节点、视口、滚动与区域关系；含未排除危险控件、歧义或变化的区域不能强行测量。

## 点击与结论

探针首先通过普通中性区域点击建立“目标未聚焦”基线，再点击原生输入内部正向控制点及视觉区域左右内部点。首个失败点最多独立复测一次。不能调用 DOM focus/blur、修改样式或合成事件来制造结果；已聚焦时点击无效留白也保持焦点，因此每点都必须先失焦。

每次聚焦观察窗口为 500ms；最多四个采样点及四次中性重置，总计八次普通点击，逐次计入动作预算。这是有界测量窗口，不是所有产品的通用时限。每个 run 最多调查两个候选；同候选、节点和有效状态可复用回执，变化后不得复用。

| 结论 | 所需证据 |
| --- | --- |
| supported | 非 low 置信候选、正向控制成功、某内部点在两次独立失焦基线下均未及时聚焦，证据稳定且无干预 |
| refuted | 正向控制及两个有效边缘点均成功；只反驳已测范围 |
| inconclusive | 无安全失焦基线、目标或状态变化、控制失败、点位不足、受干预、不支持或预算不足 |

容器或 label 正常代理聚焦是健康行为。工具保存命中元素、点击前后焦点、时间、节点身份与完整性记录。调查沿用只读网络限制和取消机制，拦截写入导致的现象不能判为站点缺陷。

原图、候选、测量及派生标注共同支持结论，服务端校验回执，不能用“截图加任意 snapshot”提升聚焦假设。标注区分视觉假设框、实际输入框和成功／失败／未知测点，不把整个视觉框宣称为不可点击。报告可查看逐点证据，业务结果与视觉 warning 分开记录。

实现入口为 `src/execution/visual-focus-runtime.ts`；候选、绑定、探针、回执与标注在相邻 visual/focus 模块。

## 验证与维护

```sh
# 免费：真实 Server / SDK / Chromium，本地固定模型
pnpm validate:visual-focus -- --preflight
# 真实模型：视觉 smoke 与诊断，使用共享费用 campaign
pnpm validate:visual-focus -- --diagnostic --campaign data/campaigns/visual-check
# 同一冻结构建、通过诊断后运行六例各三次
pnpm validate:visual-focus -- --formal --campaign data/campaigns/visual-check --diagnostic-source <本次诊断目录>
```

真实模式需要模型凭据；固定模型结果不能作为正式来源。视觉与[业务评估](arena-and-evaluation.md)可使用同一个 campaign 共享累计费用，失败及未知费用预留不因新建阶段目录清零。

私有视觉场景包括三个缺陷与三个健康反例；评分分别检查候选、实际探针、业务完成、显式收尾、证据和预算。健康代理、独立相邻控件及起始已聚焦都需覆盖。holdout 需要审核过的 fixture revision，已用于调优的场景只能作为回归；换名称或重新冻结不能恢复未见身份。

`evaluation/fixtures/visual-revision.json` 保存历史审核元数据，其中 `reviewDocument` 是审核当时的路径，可在[冻结版本的审核记录](https://github.com/FailLone/ui-sentinel/blob/31f490e/plans/visual-focus-p4-plan.md)读取。已完成计划从当前工作树删除，审核资料本身保持原字节，避免改写 fixture 身份或原批准来源。

本能力不支持任意视觉问题分类，也不证明所有像素可聚焦、任意复合编辑器可用或任何网站都能自主发现。规则发布与通用候选审批仍遵循[规则流程](rules-and-rule-library.md)。

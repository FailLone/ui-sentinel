# 产品资料与一条关键路径

R2 首批实现：普通网址扫描可附一份文本/Markdown，主 Agent 使用应用内 `product-path-2` Skill 读取资料，登记一条 1–3 步的匿名本地交互路径，通过原执行器真实操作与测量，生成来源、要求、动作和证据对应的报告。免费固定模型验收只证明产品接线、判定与持久流程；不证明真实模型提取自然语言要求的稳定性。

## 使用

启动服务时设置 `EXECUTION_URL_SCAN=1`、`EXECUTION_PRODUCT_SOURCES=1`。沿用已有主模型配置、访问边界和预算；未提供资料时保持原网址扫描。工作台选择“网址 UI 检查”，输入网址，在“产品资料与关键路径”粘贴资料名称和原文，然后开始检查。普通用户不需要提供 CSS、脚本或检查清单。

API 使用原 `POST /api/runs`：

```json
{
  "kind": "ui-scan",
  "entryUrl": "https://example.org/catalog",
  "productSource": {
    "title": "目录预览说明",
    "version": "1",
    "markdown": "# 预览\n前置条件：页面可用状态应为 Available。\n点击 Preview 后立即在状态区域显示 Ready。\n保存操作需要登录，本次不检查。"
  }
}
```

资料名称最多 160 字符，版本最多 80 字符（省略为 `1`），原文最多 24,000 个 UTF-16 code units。资料标题、版本和内容决定来源身份；原文另有 SHA-256。工作台粘贴文本即可；没有文件解析或附件上传。暂不能与 R1 探索/弹窗专用模式组合。非法或超限输入返回 400。

`GET /api/runs/:id/report` 的 `uiScan.productSource` 包含冻结原文与版本、Skill 修订、计划与选取理由、步骤/前置条件/引用、模型假设、原动作 ID、要求 ID、测量值、证据链接、通过/缺陷/未验证及未检查范围。工作台“恢复历史运行”显示同一持久报告；无需重新打开被检查网页。资料更新应创建新运行：必须重新提取、绑定和执行，不能把旧运行改成新版资料或复用旧证据作为新版通过证明。

## 工具与状态

应用内 Skill 是随代码版本化的主 Agent 指引，位于 `src/agent/skills/product-path.ts`；没有独立模型循环、个人 Codex Skill 或通用 Skill 平台。资料和页面是数据，不授予执行权限。

| 工具 | 职责 |
| --- | --- |
| `product_source_overview` | 来源身份、版本、章节标题与原文偏移；标题不是全部要求清单 |
| `product_source_search` | 最多 10 个字面关键词命中及后续游标；未命中/截断不证明要求不存在 |
| `product_source_read` | 最多 4,000 code units 的冻结原文，精确偏移、行号和后续游标 |
| `product_path_register` | 所有浏览器动作前，一次性登记路径、明确预期、引用、前置条件、假设和未检查范围 |
| `product_path_bind` | 绑定下一步当前观察中的真实控件和结果节点，实际核对前置条件；可为已冻结的后续步骤选入唯一来源匹配的新控件，不点击 |
| `product_path_status` | 查询持久记录推导的要求、动作、测量、缺口；不执行动作或修改计划 |

原文读取与结果摘要经过主 Agent 的上下文通道保留来源定位与原文；超过上下文预算时显式给出 `resultRef`，使用既有 `tool_result_read` 分页恢复。首次读取资料块、登记路径和成功绑定计为有限的新事实；重复读取不持续刷新无进展计数。总工具、时间、动作和调用预算不扩大。

每一步先冻结预期再操作。引用必须逐字匹配冻结原文；预期值必须出现在引用中。含糊或模型假设不产生可核销的效果要求。模型仍负责理解引用是否真能支持步骤和预期，程序校验不能证明自然语言理解正确。没有明确“立即/同步”依据的要求只接受正向观察，当前不以一次未出现判为缺陷，也不擅自增加 SLA。

绑定把资料效果加到既有控件的 `sourceReview/generic/effects`，共享原动作 ID、观察和测量；仍用 `page_act`、只读 `interaction_verify` 及既有调查能力。路径不得重复点击补关联，动作后的新要求不能核销原动作。前置条件在绑定和派发前均检查；前一步未通过时不允许绑定后一步。绑定后若另一个动作先发生，原绑定失效，当前保持未验证，不重放操作。

后续控件可以由前一步创建。登记时用 `targetName` 冻结原文中逐字出现的控件名称（省略时使用步骤标题）；绑定时必须有当前观察中的真实 ref，名称唯一、完整可读且控件仍为同一连接节点。`product_path_bind` 可把这个已登记步骤对应的未选控件加入原 scope，无需先调用 `exploration_update`，也不要求资料路径先完成。准入须有足够的剩余路径动作预算、后续模型调用和时间，不增加总预算；动作权限仍由原 `page_act` 检查。绑定记录保存原计划事件、目标身份、当时公开观察、预算和选取状态，动作前再次校验身份。未登记的额外控件、缺失/重名/替换目标不能借此获得准入。旧 `product-path-1` 报告保留原修订号。

## 完成与证据

资料路径登记与证据是额外必需义务。纯完成函数、执行时核销、历史投影均检查它；路径通过不能清空默认采样、其他已选项或高级 requiredChecks。路径缺陷是有效测量结论，运行可在全部其他义务有结论后 completed；含糊要求、缺少前置条件或证据失效保持 partial/unverified。

计划、前置测量和原目标绑定按事件/产物持久化并核对字节 hash。历史报告重建步骤与原动作顺序，复用原 generic/effects 产物校验与确定性谓词复算。来源版本不符、引用不符、计划事后登记、丢失/篡改证据、运行受干预均不能提供通过证明。旧报告只按原冻结来源恢复。

## 首版边界

- 一份资料、一条最多三步路径；不同的本地 click/fill 控件。不能重复同一个控件形成多步。
- 结果节点在操作前已存在且唯一；支持文本等于/包含、输入值、单选下拉可见标签、展开属性。前置条件使用同样的可测谓词；登录/角色等无法匿名证实的前置条件保持未验证。
- 纯导航作为资料路径步骤、操作后才创建的结果容器、任意复杂业务流程、Figma、多文档全覆盖、业务写入、长期记忆、向量检索后置。普通网址导航采样仍沿用原能力。
- 不把整份资料称为已验证；模型必须列出未选范围，报告总是保留全文其余内容未检查的限制。固定模型不证明真实模型提取、目标语义映射或公网泛化可靠性。

## 免费验收

在支持的 Node 24 下，使用隔离配置：

```sh
DOTENV_CONFIG_PATH=/dev/null pnpm build
DOTENV_CONFIG_PATH=/dev/null pnpm exec tsx scripts/validation/r2-product-sources.ts
# 仅运行维护者 P1 的动态控件回归与重启/准入证据篡改验证
DOTENV_CONFIG_PATH=/dev/null pnpm exec tsx scripts/validation/r2-product-sources.ts --dynamic-only
```

该脚本启动 loopback 固定模型、正式编译后服务、真实 Chromium 和隔离 SQLite；覆盖工作台/API入口、健康/缺陷、含糊要求、前置条件缺失、两步路径、其他采样 pending、未声明时限、无资料兼容、服务重启/历史恢复、原文与证据失效。所有模型地址和占位 key 均显式指向本地；不调用付费模型。输出保存在 `data/r2-product-sources/<timestamp>/`，含源码/构建 hash、请求与报告、事件、数据库和工作台截图。产物保存在运行原有 `data/artifacts/<runId>/`，不可仅复制报告 JSON 后声称证据仍完整。

动态回归固化在同一 Git 脚本，六个 `dynamic-*` 场景分别为：两步健康、第二步结果错误、后续目标缺失、重名、未登记额外按钮（绑定/普通选入/动作三重拒绝）、资料两步通过但默认样本仍 pending。结果容器从首屏存在，Details 仅由 Preview 点击创建；每个成功准入均断言未改变原默认样本池或分母。重启后检查六份持久报告，并篡改准入证据确认报告降为 unverified。新矩阵补充原八场景证据，原验收材料和维护者失败反例均保留。

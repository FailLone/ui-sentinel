## 提炼方法与证据分层

先阅读[规则约定](../rules-and-rule-library.md)。

每条先拆为“报告的现象”“该产品要求”“本库提炼推断”。观察来源仅是摘要报告，不是本轮浏览器事实；指定字体、尺寸、颜色、样式、功能条件不当作通用标准。按触发、对象、预期、违反、例外和证据方法去重。强业务条件排除；同一条里的布局/反馈可单独提炼；只有个人偏好或未说明现象的设计工作项暂缓，不静默丢弃。

缺陷规则允许在充分证据下给出条件式违反判断。体验建议涉及合理取舍，只生成审查意见，不能因建议未采用而判 fail。没有外部标准引用或数值门槛；本轮无需联网核验标准，也没有宣称符合 WCAG 等规范。将来引入外部标准必须记录官方原文、版本与适用条件，未核对则待核实。

## 状态与判定边界

文档状态和运行时结果分离。`fail` 需要适用、目标与违反事实；`pass` 需要适用且实际完成检查；`unknown` 包括适用性不明、证据不足、目标歧义/陈旧；`not-applicable` 仅在明确不满足触发条件时使用。没有适用规则不代表通过。R005 已采用独立审查材料，不把建议强行映射为四态；其他审查项尚未实现。

首次提炼时每条健康反例均标“合成示例”；后续 D004/D010 及第二批 D005/R005 的限定样本完成测试，见对应条目的实现记录。定义清楚的规则也可能只有低充分性的源案例，如点击拦截、图像比例及 token 解析；它们依然是候选。UIK-D010 记录既有 `overlay-blocking` 的来源关联，不复制实现或改变已批准契约。加载/动效建议不替代现有 `response-time`，不新增超时值。

正常禁用、模态背景不可交互、下拉覆盖、部分显示轮播、有意裁切、按需加载、自适应卡高、品牌固定底色与点击焦点环都有合法情形。“所有元素都一样”“所有 CTA 固定在底部”“禁止插画”“永远持续滚动”均不是本库规则。

## 增量维护与后续验证

1. 新材料先给来源记录追加稳定编号与内容指纹；现有 `SRC-FAIL-*` 固定，不按新文件行号重排。原 ID 恢复后增加 Jira 别名；epic/关联 ID 不可冒充原 ID。原文件变更时记新快照指纹并保留旧定位。
2. 检索现有规则，按触发/对象/预期/违反/例外比较。扩充来源只增加证据关系；调整判定需升文档修订。合并保留最早稳定 ID，旧 ID 留弃用指针及原因，不重新编号。
3. 同时更新规则页、目录、来源映射和去重日志，说明缩小/扩大范围；来源状态关闭不自动升级规则状态。
4. 补异常、健康、触发不成立与证据不足样本；绑定另覆盖名称变化、歧义、布局变化和目标失效。完成实际测量前不得把合成例标为 pass。
5. 实现、执行验证、首次批准与启用是之后独立工作，实现轮同样不调用学习/批准命令。首次审批遵守项目已有人工审阅流程。

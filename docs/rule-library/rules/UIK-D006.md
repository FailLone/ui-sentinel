# UIK-D006 · 过渡中的数据状态不得被误报为终态

- 类型：缺陷检查规则；主题：反馈与状态一致性。
- 文档修订：1；首次建立：2026-10-08（Asia/Shanghai）。
- 当前状态：候选知识，待验证；未实现、未验证、未批准、未启用。
- 来源摘要：3 条（含 0 条归并摘要；不是独立验证次数）。

## 一句话原则

仍在加载或退出的中间状态不应被呈现成与已知过程不符的失败或空结果。

## 适用条件

有当前对象/请求的可信进行中事实，或者内容未清空但面板正在关闭；能关联同一轮操作。

## 不适用情形和正常例外

已确认真实失败/空结果；重试时保留上一轮明确标注的失败；可辨认的旧内容刷新；骨架、spinner 或其他准确反馈均可。

## 可观察的违反条件

在没有相应终态依据时显示确定的失败或空结果，或关闭动画暴露仅因内部清理而产生的空屏文案。

只有适用事实、目标绑定与违反证据均完整时才可判 fail；缺证不视为通过。

## 如何识别检查对象

按请求/对象身份绑定内容区及反馈区，必须区分不同请求、重试与用户切换；不用业务价格字段决定状态。 目标引用须来自当前观察；引用过期、同名多目标或操作身份不明时重新绑定或返回 unknown。

## 检查步骤

1. 记录加载/关闭前的对象身份与非空状态。
2. 沿同一操作采样开始、进行中和终结/卸载时间线。
3. 比较文案语义与当时已知状态；检查上一轮反馈是否明确隔离。

请求/生命周期事件、带时间的画面或录屏、当前对象身份。单张空屏不能说明尚在加载；来源只给建议无事件时 unknown。 本批只有二次整理的文字报告，未观察真实 UI，未取得截图/设计附件；因此来源记录不能直接产生实测 pass/fail。

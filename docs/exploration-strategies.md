# 探索策略与未知问题发现

日期：2026-09-22  
状态：补充设计，本文提出的策略注册、路由、焦点采样协议及新靶场尚未实现或通过真实模型验证。  
范围：问题线索的产生、探索策略契约、调用时机、交互证据、漏报复盘与独立评估。

## 1. 需要补上的能力

能够验证一个给定问题，不等于能够自主发现这个问题。Agent 顺利完成购买或填写表单，只能证明它走过的操作路径成功，不能证明真实用户可能采用的操作方式都合理。

例如，无边框输入框周围存在大量留白，整体背景让用户认为整块区域都可输入，但实际 input 很窄。语义定位后直接输入、调用 focus，甚至视觉定位后点击中心，都可能完全绕过缺陷。

系统不能依赖“模型足够聪明，会自己想到所有问题”。探索策略用于引导 Agent 主动寻找线索，提高有限预算内的发现概率；不承诺穷举，也不能用策略列表限制 Agent 提出列表外的假设。

## 2. 策略、规则和知识的区别

| 对象 | 回答的问题 | 示例 |
| --- | --- | --- |
| 探索策略 | 去哪里找，尝试哪些变化来产生线索？ | 比较视觉可交互范围与实际响应范围 |
| 产品要求 | 当前产品应当怎样，依据是什么？ | 设计规范要求整个搜索容器可点击输入 |
| Rule | 已有事实是否满足一个明确要求？ | 约定输入区域内的有效采样点击未触发预期聚焦 |
| 执行能力 | 怎样可靠获得事实？ | 坐标点击、焦点观察、命中测试、截图 |
| 靶场及评估器 | 策略是否提升发现率，是否增加误报？ | 缺陷输入框、容器代理聚焦、独立图标按钮等变体 |

探索策略是知识库中“探索经验”的结构化形态，不另建一套互不关联的知识系统。一个策略可以产生多种问题假设，一个假设可以由已有规则或工具组合验证。

策略可以复用确定性的采集程序，但不等同于“一条策略对应一个判定脚本”。视觉范围和语义预期可能需要模型推断；一旦可确定性采集、判断，就交给执行层与规则层。

## 3. 策略的最小契约

以下是拟定结构，不是当前可调用 API：

```yaml
id: interaction.visual-hit-area
revision: 1
status: candidate
intent: 发现视觉可交互范围与实际响应范围的不一致
appliesWhen:
  - 观察到输入、按钮、卡片等可交互组件
  - 视觉容器与实际交互节点范围可能不同
requires:
  - 同一页面状态的截图与元素几何信息
  - 坐标点击、命中测试与响应观察能力
probes:
  - 推断视觉范围，并记录依据、歧义和独立子操作
  - 在中心、留白和边界附近选择少量采样点
  - 验证每个点的实际响应与预期是否一致
alternatives:
  - 外层容器通过事件代理完成了预期操作
  - 图标或子区域具有独立的合理操作
  - 视觉范围不明确、组件禁用或仍在加载
budget:
  maxTargets: 2
  maxProbePointsPerTarget: 5
stopWhen:
  - 预算耗尽或继续采样需要未授权副作用
  - 状态变化导致原采样计划失效
outputs:
  - hypothesisRefs
  - evidenceRefs
  - coverageAndUnknowns
```

上述预算只是示例，不是正确性阈值。运行的剩余时间、模型、动作和资源预算始终具有约束力。实际策略还应记录来源、适用项目/角色、风险、允许副作用、修订和评估记录。

策略定义不写死产品元素 ID、文案或坐标。执行时的 ProbePlan 可以引用当前快照中的目标和坐标；这些是有状态版本的临时定位，不是跨页面通用规则的一部分。

## 4. 何时使用与怎样检索

```text
观察页面或重要新状态
  → 建立页面与组件语义，运行适用的基础检查
  → 按当前状态检索策略摘要、相关要求和历史案例
  → 结合风险与预算，选择调查方向或自拟新方向
  → 展开选中策略，形成有边界的采样计划
  → 获取线索，登记可证伪假设
  → 复用规则或组合工具验证
  → 保存结论与未覆盖范围，更新下一步计划
```

策略既可以在进入页面时使用，也可以在路径完成、错误恢复、弹窗出现或布局变化后使用。不能只在操作失败时启动体验探索，否则成功路径中的问题仍会被跳过。

上下文只加载候选策略摘要，选中后才展开步骤、反例和证据要求。按组件语义、页面状态、近期变更、历史漏报和成本检索，不扫描整个策略库。轻量事实路由可提出候选，Agent 判断其价值；没有命中策略仍可继续探索。

规划应为非中心点击、边界条件或替代操作方式保留显式预算，预算多少由任务策略配置并通过评估调整。若未执行，应记录原因，不能把预算耗尽当作检查通过。相同状态和采样计划复用已有结果；布局或状态变化后重新确认。

## 5. 示例：输入框的视觉范围与聚焦范围不一致

### 5.1 建立假设

从原始截图识别背景、留白、文字、图标和相邻布局，推断用户可能认为可输入的区域。DOM 几何用于解释结构，不能直接把 input 的矩形当作用户的视觉预期。

分别记录：视觉范围及其推断依据、真实编辑节点范围、期望响应、产品要求引用、合理的独立操作区。无边框且无背景时，范围可能不明确，不能仅因模型画出了矩形就判为违规。

### 5.2 用真实操作采集

1. 保存页面状态、原始截图、视口、滚动位置和坐标系。截图缩放与设备像素到 CSS 像素的换算必须明确。
2. 选择安全且数量受限的点：input 内部作为对照，再选择视觉区域内的留白或边界点；排除已识别的独立操作。
3. 每次采样前通过正常、安全的交互将焦点移出目标并验证。若无法安全失焦，标记该次无法判断，不能沿用已有焦点。
4. 使用可记录的坐标点击验证该位置。不得把该次操作自动纠正到 input 中心，也不得使用强制点击、直接 focus 或修改页面来掩盖问题。
5. 保存点击前后焦点、命中节点、时间和可见响应。命中外层容器不代表失败，它可能通过代理事件正确聚焦。
6. 对复合组件、contenteditable 和 Shadow DOM 解析实际编辑目标；仅检查顶层 document.activeElement 不足时，标记能力缺口或使用专用观察器。
7. 允许合理的异步聚焦，记录观察窗口。若页面重渲染、滚动或弹层改变了现场，重新观察后再决定是否采样。
8. 对疑似失败点在同等前置条件下复现，排除加载、禁用、覆盖物、状态变化等替代解释。

失焦本身可能触发校验、自动保存或网络请求，也必须受执行层权限与资源约束。不能为了检测点击区域而对未知业务容器进行无边界扫点。

### 5.3 输出结论和证据

“该坐标点击后没有聚焦”是操作事实；“用户会认为这里应该聚焦”是独立的预期判断。两者分别保存。

- 明确产品要求与可复现的相反结果，可以支持缺陷结论。
- 仅有视觉预期推断，报告需标明推断依据；歧义未消除时保留 candidate / inconclusive 或体验建议。
- 对照点失败、焦点不可观测或状态不一致，不能假定是点击区域问题。
- 有限采样只能说明已测点的行为，不能宣称测出了整个有效交互区域。

报告保留原图，另生成标注图：区分推测的视觉区域、实际编辑节点范围，以及成功/失败采样点。附上每点动作和焦点记录，不把视觉估计画成已测量的事实。

## 6. 探索日志与漏报复盘

在现有 Run、Hypothesis、Action 和 Evidence 记录上关联以下拟定字段，不保存模型隐藏思维链：

- 策略 ID/修订或自拟策略说明、选择依据和预期来源。
- 页面状态、目标、计划采样点、实际执行点和剩余预算。
- 点击前后焦点、命中、可见响应、观察窗口和证据引用。
- 支持、反驳、未知结果，以及停止或跳过原因。

漏报复盘至少区分：没有观察到该区域、没有提出假设、未选择适当策略、没有执行有效采样、采集能力不足、预期或判定错误、证据在汇总时丢失。

相应改进可能是策略、工具、规则、知识或报告逻辑的更新。不能把所有漏报都处理为新增 rule 或追加一段提示词。

## 7. 靶场与效果评估

为此类交互建立候选案例集，至少包含：

| 变体 | 独立预期 |
| --- | --- |
| 视觉范围宽、实际 input 窄，留白不响应 | 在预期明确时应发现问题 |
| 同样外观，容器点击正确代理聚焦 | 不应误报 |
| 图标有独立操作，其他输入区域正常 | 不应把独立操作判为聚焦失败 |
| input 已聚焦后再点击留白 | 评估采样是否正确建立失焦前置条件 |
| 视觉边界模糊，缺少产品约定 | 应保留歧义，不能强判 |
| 合理异步聚焦或复合编辑组件 | 不应只凭即时焦点或顶层节点误报 |
| 改变文案、布局、缩放或组件实现 | 检查策略是否依赖固定位置和实现 |

必须分开测两种能力：

1. 定向验证：明确提示可疑问题，测量取证与判定是否可靠。
2. 自主发现：只给正常的检查目标与允许操作，不提示具体缺陷或位置，测量是否主动产生假设、执行有效采样并报告。

在相同版本和预算下对比无策略引导与有策略引导，重复运行并记录发现率、误报率、候选比例、采样覆盖、时间及模型/动作成本。不得通过减少正常业务覆盖来虚增体验发现指标，应同时记录业务覆盖。

私有评估器独立验证场景和证据；被测 Agent 不接触故障变体答案。此处已讨论的输入框案例属于开发/回归案例，不能再充当未见问题的泛化证据。泛化需独立维护未参与调优的其他交互案例。

## 8. 演进与当前边界

反馈 → 定位漏报环节 → 提议策略/工具/规则修订 → 建立缺陷与合理反例 → 独立评估 → 审阅发布 → 固定修订并持续回归。

Agent 可以提出候选策略，但不能自行修改正式答案或声称更新已有效。只有稳定、适用条件明确的判断才沉淀为 rule；仍需探索的部分继续保留在策略中。

当前项目已有观察、动作、假设和发现记录等基础能力，但这不代表已实现本文的视觉范围推断、受控焦点采样、策略库路由和完整评估。本次仅补充设计，不改变最小验证 C0–C5 的验收范围，也不把真实模型尚未验证的能力描述为已完成。实施时应另在 plans/ 编写开发计划。

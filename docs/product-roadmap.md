# 产品目标与 Roadmap

目标是让团队从网址和可追溯要求出发，发现有证据的 UI/UX 与交互问题，并把稳定的检查沉淀为可重复执行的规则和路径。公开要求、观察事实与模型假设分别保存；检查完成、业务成功和网站质量是不同结论。

## 已实现能力与当前缺口

| 目标 | 主干已有能力 | 当前缺口 |
| --- | --- | --- |
| 从网址开始检查 | 匿名、有界扫描，规则检查、局部动作测量及覆盖报告；默认关闭 | 陌生网站自主探索稳定性、复杂动态页面覆盖和完整真实模型验收仍有限 |
| 提高探索效率 | 可选程序优先探索，候选前沿、状态/路径、去重、公平性和有限恢复 | 任意网站全状态遍历未实现；可选 Jev 排序收益未获通用证明 |
| 用资料约束效果 | 一份文本/Markdown到一条1–3步匿名本地路径，原文引用、登记、绑定及原动作测量 | 多文档、Figma、登录角色、导航路径步骤及操作后新建结果容器未支持 |
| 复用已验证经验 | 保存健康路径，同精确入口/同来源版本重新执行；失效后保留事实并安全交回 | 无结构迁移、自动修订/淘汰、跨项目检索；模型额外文字解释仍未验证 |
| 重复检查时识别变化 | 从同入口健康历史选择基线，对实际到达步骤比较公开依赖和叶节点事实，重新测量 | 不证明整站相同，不只执行变化片段；大历史性能和真实资料语义变化后的规划仍待验证 |
| 扩展检查知识 | 运行时规则、人工批准的声明式候选、调查程序和独立知识目录 | 知识候选不等于实现；缺事实时自动生成取证任务尚未实现 |

上述能力的具体约束和用法从[文档首页](README.md)进入。购物与导出提供两个版本化业务契约和可重置靶场；它们不代表任意业务接入完成。

## 下一步方向

1. **提高普通网址入口的可用性。** 以已有健康/缺陷/unknown 反例定位目标解析、动态入口可达性、规则适用与证据闭合的问题。分别验证确定性接线和真实自主选择，保留真实失败；未合入的实验或修复不计入主干能力。
2. **巩固资料与复用路径。** 根据实际问题补充来源变更、节点失效、未到达步骤及只读交回反例，再评估局部修订和更复杂路径。新计划始终取得本次证据。
3. **逐项扩展规则支持范围。** 优先补适用依据、健康反例与可信绑定；图像语义、复杂绘制和体验建议不能仅凭几何或主观偏好自动判错。
4. **补可靠性与评估缺口。** 定向调查[已知持久异常和回归波动](known-issues.md)，将成熟反例加入[长期靶场](counterexample-arena.md)。真实模型比较固定样本、构建、预算和评分，不能用固定回复代替。

PRD/Figma 自动接入、复杂业务、多机调度、跨项目知识和通用自动规则发布属于后续方向，尚无交付日期或服务承诺。是否进入下一阶段由具体需求、可验证范围与证据决定，不由阶段编号推定。

## 演进原则

Rule 定义质量约束和判定，应用内 Skill 指导 Agent 理解与使用工具，程序承载稳定步骤；运行检查任务只是执行实例，不另建重复规则库。见[设计口径](rules-and-rule-library.md#设计口径ruleskill程序与运行任务)。

每次接收变更更新对应指南、限制和靶场目录；不在本页追加测试成绩、费用或会话时间线。历史 R0–R4 的范围、失败与冻结证据见[历史索引](archive/README.md)，使用项目无需先阅读这些记录。

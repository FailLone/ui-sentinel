# 有界界面遍历：运行能力与实验

遍历核心已从评估目录移入运行代码，提供独立的本地 HTML 检查入口。**默认 `ui-scan` 仍采用原有抽样策略，未改为状态图遍历**。因此这里的结果证明新模式的机制与有限靶场表现，不代表原默认产品流程已完成改造，也不代表任意网站可穷尽。

## 代码与职责

| 模块 | 责任 |
| --- | --- |
| `src/inspection/exploration-graph.ts` | 纯状态账本、精确身份、进入边、待查动作、循环与汇合统计 |
| `src/execution/exploration/browser.ts` | 活动弹窗/页面采集、控件命名与区域、有限输入动作、稳定等待、执行前校验 |
| `src/execution/exploration/run.ts` | 完整队列、分支恢复、分页读取、范围排除、预算、证据和完成判定 |
| `src/agent/exploration.ts` | 真实 Mastra 工具调用；Agent 补读页面、解释控件用途并选择已读动作；兼容旧预期检查模式 |
| `scripts/cli/explore-local.ts` | 使用正常项目模型配置检查用户指定的本地 HTML；浏览器网络禁止 |
| `evaluation/state-graph/` | 简单与复杂靶场、独立评分和免费固定决策驱动 |

程序负责完整枚举支持的控件、维护待查队列、校验引用、执行动作、保存证据及决定是否结束。Agent 负责理解公开信息、提出需要读取的内容、解释控件用途与选择动作。Agent 不能删除待查义务、宣称状态等价或直接标记通过。

本轮新增 `mode: recognition`：Agent 通过 `explore_control` 返回 ref、简短用途和页面原文引用，不必预测下一页标题。程序要求引用来自实际交付的正文片段或所选控件的语义信息；随后记录真实目标节点，边的 verdict 为 `observed`，不代表通过了缺陷检查。`recognitions` 保存每个动作的解释与依据。引用可溯源只是证据约束，不能自动证明解释正确，因此另用独立语义任务评分。

运行 API 默认保留旧的 `inspection` 兼容行为；本地 CLI 已明确使用 `recognition`。旧模式仍要求标题/正文预期，并支持 `report_gap`：该动作进入 `unverifiedActions`，其他分支继续，未解决项阻止穷尽结论。认识模式不会因未知目标标题而要求跳过控件。

当前输入等价类由调用方显式给定。风险排除也由调用方控制并逐项记录；不是根据 Agent 一句“这个不用测”就跳过。未经检查的排除项不计作通过。

## 表达与分页

浏览器采集活动模态框（最上层）或页面的全部受支持控件，不沿用原采集器的 180 个上限。每个动作记录名称、描述、角色、命名区域、启用状态、当前值、操作类型、有限测试值及内部定位信息。可支持原生按钮、链接、文本输入、textarea、select、checkbox、summary，以及 button/tab/checkbox 角色的点击。

决策默认只发送 8 个待查动作、400 字符正文摘要和一页区域目录。`read_page` 可以按 offset 继续读取控件、区域目录或 2000 字符的正文页。所有原始观察保存在证据中。已查控件移出队列后，后续控件自动进入下一轮候选页；分页不减少总待查量。动作只能引用本轮实际提供或补读过的 ref。

单页决策数据上限 32768 字节、单次决策最多 8 次补读。过大的单项不会默默裁剪成已审查，而是保留 partial。区域筛选后的 offset 相对于该区域；越界读取返回总数与正确起点，不清空待查队列。Agent 适配器支持有界批量补读；同轮重复读取返回缓存，随后只允许选择动作（旧检查模式还可 `report_gap` 明确保留未完成项），防止无限重读。输入与模型用量均记录。报告分别提供 `discoveredActions`、`deliveredActions`、`unreadActions`、`checkedEdges`，并区分 disabled、excluded、remaining。

## 状态、路径与去重

精确身份包含 URL、活动区域标题、全文、控件语义属性/当前值以及调用方提供的业务上下文；临时 ref 和 CSS 定位串不进入身份。只有观察完整且上下文已知时才合并。相似分组只作报告参考，不会据此跳过检查。

`context()` 必须覆盖所有影响后续行为的隐藏业务/历史状态；不知道就返回 `null`。它不是截图或 DOM hash 能自动推断出来的事实。历史靶场中，两次可见页面完全相同，但 `armed` 不同，所以保留两个节点。普通静态靶场可明确声明无额外隐藏状态；该声明不能套用到任意网站。

不同路径进入同一节点时，每条进入边都独立执行和测量，后续队列复用。自循环仍探索一次并记录；认识模式不把它判作缺陷。正文不同或输入值不同的相似页面不会合并。同名动作依靠命名区域区分；仍有歧义则停止并报告，绝不任意挑选第一个。

程序优先当前分支；当前分支结束后恢复最近发现的未完成节点。只有 `replaySafe` 显式成立才允许 reset/replay，每一步都验证目标指纹。恢复失败、未知上下文需要恢复、状态意外变化、过期动作都停止并保留未完成项。状态合并忽略定位串，但执行前另外校验被选控件的定位绑定；即使语义指纹没变，包装结构变化也不能让旧定位误点邻近按钮。探索动作和恢复动作分开计数。会产生订单、发送消息等副作用的路径不能仅通过“再次点击”恢复。

## 完整性与终止

DOM 稳定观察默认等待 120ms 静默窗口，最多等待 2500ms，并识别 `aria-busy`。这能处理靶场的异步反馈，但不能证明没有更晚的定时器；调用方仍须提供合适的稳定条件与状态契约。

检测到 iframe、canvas、开放 Shadow DOM、虚拟列表标记、未支持的角色、无界输入等时记录 gap，不能报告穷尽。关闭 Shadow DOM、委托事件、自定义渲染和无标记虚拟列表未实现可靠发现，因此不支持对未知网页承诺采集完整。当前名称提取是有限 DOM 适配，不是完整浏览器无障碍树实现。

默认预算是 100 次决策、400 次操作、100 个状态、深度 20、10 分钟；超过预算仍保留 remaining。disabled、未解决的 Agent 动作缺口、未知上下文、不完整观察均阻止 `bounded-scope-exhausted`。该状态仅表示声明范围内动作遍历完毕；仍可包含失败边，不等于“页面无缺陷”。标题相等/正文包含只用于旧检查模式，不属于本轮认识模式验收。

## 操作者入口

```sh
pnpm explore:local /absolute/path/page.html /absolute/path/scope.json --real
```

`scope.json` 示例：

```json
{
  "version": 1,
  "stateContract": "dom-complete-resettable",
  "inputValues": { "Query": ["", "alpha"] },
  "excludedControls": [
    { "name": "Delete workspace", "reason": "outside-read-only-scope" }
  ],
  "maxDecisions": 80,
  "maxModelCalls": 100,
  "maxClicks": 400
}
```

`dom-complete-resettable` 是操作者对该本地页面的明确断言：相关状态由 DOM 表达，重置可恢复且没有外部副作用。不满足时使用 `unknown`，它禁止合并和自动重放。复杂隐藏状态应通过运行 API 的可信 `context()` 适配器接入，不能填一个常量伪装已知。

CLI 使用正常 `AGENT_MODEL` 配置（包括已有的 OpenAI 兼容端点配置），仅调用 Agent，不需要视觉模型。HTML 在新浏览器上下文里载入，HTTP 和 WebSocket 请求都禁止；外链资源不会加载，因此需要自包含 HTML。输出 `data/exploration/<timestamp>/` 包含范围、HTML hash、模型输入/结果、每步截图/观察和报告。CLI 提供调用数量上限，**不提供美元计价上限**；需要费用约束时由模型端点的预算网关承担。报告 partial 或有失败边时返回非零退出码。

运行 API 接收已有 `Page`、reset、context、decide、evidence 等适配器。嵌入其它服务时，访问边界、页面生命周期、存储/会话隔离及副作用授权由宿主承担，不能绕开现有 URL 扫描网络策略。

## 可重复验证

使用项目支持的 Node 24、锁文件依赖和 Playwright Chromium：

```sh
pnpm exec vitest run evaluation/state-graph src/agent/exploration.test.ts
pnpm exec tsx scripts/validation/state-graph-recognition.ts --preflight
pnpm exec tsx scripts/validation/state-graph-recognition.ts --real
```

认识靶场从复杂页面扩展，去掉普通控件提前声明的目标标题，加入无操作自循环和名称含 Delete 的正常指南入口。完整图有 14 个状态、56 条范围内边，另有一个显式排除项。历史靶场有 4 个状态、6 条边：两个 Session 页面可见内容完全一致，由可信 context 区分。

程序机制压力测试将汇合入口扩展到 190 个，总计 218 条边，检查末尾功能没有因 24/180 上限丢失。该测试使用固定决策，不作为真实 Agent 全图成绩。真实全图实验使用 28 个汇合入口，逐步探索嵌套弹窗、相同标题不同正文、区域内同名按钮、有限输入状态、异步报表、返回环和自循环。每个入口都执行，下游相同状态只展开一次；范围排除必须精确匹配，不能误剪掉邻近指南。

独立理解题使用同一个真实 Agent 适配器，答案不进入模型输入：

- 在 190 个入口之后寻找指定功能，验证区域目录与按需补读。
- 在同名 Open 中选择 Beta 记录。
- 在当前嵌套弹窗中选择预览，不误操作背景控件。
- 读取正文末尾的规则，再选择离线支持入口，并引用支持选择的规则。
- 选择填写 alpha 的有限输入动作，而非提交。
- 打开删除历史的指南，区分指南和真正的删除动作。

全图评分检查独立矩阵中的每条真实转移、遗漏、意外目标、重复展开、重复节点、排除和未读项。理解题另检查目标 ref 对应的语义/区域/操作值、实际读取与引用。两类成绩分别报告，不用缺陷命中率作为本轮门槛。单次合成靶场实验不构成泛化率或“轻松理解”的统计证明。

`--preflight` 使用固定首项决策与真实 Chromium，免费但不是智能能力验收。`--real` 使用真实 Mastra Agent，先做工具联通探针；默认固定 `wafer`，不重试、不回退。运行前检查端点能力和价格。理解题、两组遍历与探针共用单批 1 美元、120 次请求上限，费用未知即停止；旧批次的未知费用保留，重新启动不是续跑。

产物位于 `data/state-graph-recognition/<UTC 时间>/`：冻结源码/锁文件 hash、提示词、实际模型/服务商、每次输入输出、理解题答案、截图与转移证据、完整图、评分及费用账本。运行前后核对源码，失败同样保留。输入字节统计不含系统提示与工具 schema，真实 token 以网关账本为准。

旧 `state-graph.ts` 与 `state-graph-complex.ts` 保留标题/正文预期检查实验及原始成绩，属于历史检查基线，不能把它们改名为认识模式已通过。

## 尚未完成的产品接入

默认 URL 扫描的抽样上限与旧报告/完成证明保持原样。将新遍历作为正式 URL 扫描模式还需要：契约/API/工作台入口、现有串行工具与网络边界的接合、持久化图与完成证明、可验证的业务状态/恢复适配、虚拟列表和 iframe/Shadow DOM 支持，以及同条件 A/B 与独立样本验证。

本实验使用明确公开语义描述、可重置页面和有限输入。真实模型跑通这些用例也不能推导出开放网站泛化率，更不能承诺对无限输入与任意隐藏业务状态完全穷尽。
